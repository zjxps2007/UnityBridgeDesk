# UnityBridge Desk · Windows 시험 배포본

**전달용 ZIP을 받았다면** 압축을 모두 풀고 맨 위의 **UnityBridge Desk 실행.exe**를 더블클릭하세요. 내부 파일은 `app` 폴더에 모여 있습니다. 실행 파일과 `app` 폴더를 함께 보관하세요. `처음 읽기.txt`에 시작 순서가 있습니다.

`UnityBridgeDesk.exe`를 실행하세요. 이 폴더 전체를 함께 보관하고 이동하세요. `worker/`와 DLL을 제거하면 실행할 수 없습니다. .NET 런타임을 포함하므로 별도 .NET 설치나 브라우저·UI 서버가 필요하지 않습니다. Windows 11 x64에서 검증한 시험 배포본이며 공개 배포용 서명·설치 프로그램·자동 업데이트는 포함하지 않습니다.

## 준비할 것

- 사용하려는 Unity 프로젝트와 해당 버전의 Unity Editor 실행 파일.
- Bridge 0.2.0·0.2.1은 **벤치마크 → 실험 환경 자동 준비**에서 공식 파일을 받아 준비할 수 있습니다. 이미 찾거나 검증해 보관한 파일은 재사용합니다. 다른 버전은 [공식 배포](https://github.com/zjxps2007/UnityBridge/releases)의 Windows CLI와 Connector 폴더를 직접 등록합니다. 이 ZIP 자체에는 Unity·Bridge 바이너리가 들어 있지 않습니다.
- AI 기능 사용 시 Codex 실행 파일, 모델 ID, 추론 수준, 파일 인증이 설정된 전용 Codex 홈. 인증 키를 앱 입력란에 붙여 넣지 말고 `auth.json`을 보유한 홈 폴더의 경로를 지정하세요. 고정 명령 벤치에는 AI 설정이 필요하지 않습니다.

## 세 도구의 사용법

처음 벤치를 사용한다면 **벤치마크 → 1 준비 → 실험 환경 자동 준비**를 먼저 누르세요. CLI·Connector 검색, 없는 파일 다운로드, 해시 검증, 버전별 보관·등록·선택과 설치된 Unity Editor 연결을 한 번에 수행합니다. 현재 선택한 프로젝트를 우선 사용하며 후보가 하나면 자동 선택합니다. 여러 개라면 카드에서 고르세요. 파일은 `%LOCALAPPDATA%/UnityBridgeDesk/releases/<버전>/<보관 ID>/`에 보관하므로 개발 PC의 임시 경로에 의존하지 않습니다. 다음 준비는 검증된 파일을 인터넷 없이 재사용합니다.

필요한 Unity 설치와 AI 모델·로그인 설정은 별도로 완료해야 합니다. 준비 중에는 **준비 취소**를 사용할 수 있고, 실패해도 검증이 끝난 파일은 다음에 재사용합니다. **준비 완료 → N개 시행 시작**을 눌러야 복제본 생성·Connector 적용·Unity 기동을 수행합니다. 준비만 눌러서는 Unity나 AI를 실행하지 않습니다. 아래 보관함 흐름은 다른 버전이나 직접 파일을 등록할 때 사용합니다.

상단 **보관함 → 빠른 설정**에서 자동으로 찾은 프로젝트와 Bridge 조합을 고르세요. 기본 위치나 Unity Hub에서 찾지 못하면 **다른 위치의 폴더 추가**로 프로젝트 또는 압축을 푼 Bridge 폴더를 한 번 지정합니다. 다음에도 해당 위치를 기억합니다. CLI와 Connector가 같은 폴더에 있으면 조합으로 제안하고 등록 시 파일과 해시를 확인합니다. 서로 같은 버전인지 표시된 경로도 확인하세요. 별도 조합은 옆 탭에서 구성할 수 있습니다.

기본 대상을 선택한 뒤 **설치·관리 / AI 작업 / 벤치마크** 탭을 선택하세요. 작업 준비의 **Unity Editor / AI 프로그램 · Codex / Codex 로그인 정보** 카드에서 자동 확인 결과를 봅니다. 찾은 항목은 그대로 사용하면 됩니다. Unity는 프로젝트와 같은 버전을 연결하고, Codex는 데스크톱 설치 위치와 기본 설치 폴더도 찾습니다. 여러 후보는 한 번 선택하고, 다른 위치는 **위치 확인 · 직접 지정**에서 고릅니다. 유효한 기존 경로는 **다시 찾기**를 눌러도 유지합니다. 찾지 못한 항목에는 다음 행동과 **설정 방법**을 표시합니다. 모델·실행 허용 여부는 직접 정합니다.

로그인 파일이 없다면 **Codex 로그인 정보 → 설정 방법**을 확인하세요. 현재 AI 실행기는 `auth.json`이 있는 폴더를 사용합니다. Codex에 로그인되어 있어도 운영체제 자격 증명 저장소를 사용하는 경우에는 이 파일이 없을 수 있습니다. 카드의 공식 안내에서 파일 저장 방식을 확인하고 로그인 후 다시 찾으세요. 고정 명령 벤치에는 AI 설정이 필요하지 않습니다.

1. **설치·관리:** 실행 구성에서 Editor와 릴리스를 선택하고 **구성 확인**으로 대상·변경 범위를 검토한 뒤 실행합니다. 프로젝트의 Bridge 의존성을 관리 폴더의 Connector로 연결하고 실제 응답을 확인합니다. manifest·lock 백업을 보존합니다. 실패하면 Bridge 의존성만 복원하며 다른 변경은 유지합니다. 첫 설치는 해당 프로젝트의 Editor를 닫고 진행하세요.
2. **AI 작업:** 도구의 초안 화면에 자연어 지시를 입력하고 **실행 구성**에서 Editor·릴리스·AI 연결을 지정합니다. 검토 후 실행하면 선택한 프로젝트의 파일을 변경합니다. 실행마다 새 대화를 만들며 같은 작업의 후속 지시만 같은 대화를 사용합니다. 일반 작업의 자동 확인은 Bridge 연결·컴파일 상태까지이며 임의 요구의 기능 완성을 보증하지 않습니다.
3. **벤치마크:** 탭을 열면 **1 준비 / 2 진행 / 3 결과**가 바로 보입니다. 아래 순서대로 사용하세요. 매 시행은 새 프로젝트 복제본과 새 Unity 프로세스를 사용합니다. AI 과제마다 새로운 인증 전용 홈과 대화를 사용합니다. 기준 프로젝트를 직접 수정하지 않습니다.

설치·관리와 AI 작업에서 보관함 선택을 바꾼 경우 실행 구성의 **보관함의 현재 선택 불러오기**로 새 초안에 반영하세요. 벤치 준비 화면은 보관함 변경을 바로 반영하고 재검토를 요구합니다. 이미 실행 중인 대상은 이후 보관함 변경의 영향을 받지 않습니다. 앱 전체에서 한 작업씩 실행하며 다른 도구의 실행 요청은 대기합니다.

## 벤치 시작과 결과 확인

1. **1 준비:** 처음에는 **F01 응답 시험 선택 → 실험 환경 자동 준비**를 누르세요. 고정 명령만 켜고 독립 반복 2회, 준비 호출 1회, 준비 후 측정 호출 3회로 0.2.0·0.2.1을 준비합니다. AI 계정 설정 없이 사용할 수 있습니다. 다른 버전은 보관함에서 등록·선택합니다.
2. **준비 완료** 후 아래 고정 버튼 **N개 시행 시작**을 누릅니다. 누락된 설정이 있거나 조건을 바꿨다면 안내를 완료하고 **구성 확인**으로 다시 검토합니다. 두 버전의 기본 F01은 2조건 × 2버전 × 독립 2회 = 8개 시행입니다. ‘자동 준비’나 ‘구성 확인’만 눌러서는 실제 벤치가 시작되지 않습니다.
3. **2 진행:** 현재 버전·조건·반복, 준비/측정/정리 단계, 완료 수·경과 시간을 확인합니다. Unity 준비 동안 완료 수가 움직이지 않을 수 있습니다. 진행 막대는 완료 시행 수이며 남은 시간 비율이 아닙니다. 중단은 아래 **실행 중단**을 누르고 정리가 끝날 때까지 기다립니다.
4. **3 결과:** 완료한 실행의 결과가 자동으로 열립니다. 이전 기록은 **지난 결과 보기** 또는 결과 탭에서 고릅니다. 성공·실패·중단 수 → 같은 조건의 버전별 시간 → 독립 시행 수 순서로 확인하세요. 오류는 **원시 기록·오류 상세**, 파일 저장은 **선택 결과 내보내기**입니다.

F01의 **Unity 준비 후 첫 명령**은 Unity 기동·컴파일 완료 후의 첫 측정 응답입니다. 프로젝트 생성부터의 시간이 아닙니다. 화면은 **ms/호출**로 표시하며 낮을수록 해당 조건의 응답이 빠릅니다. 준비 후 조건은 시행 안의 호출 평균을 구한 뒤 독립 시행끼리 비교합니다. 원시 CSV의 `workMs`는 호출 시간 합계이므로 화면 값과 구분하세요. 준비·검증·정리는 별도입니다. 작은 표본으로 종합 우열을 판단하지 않으며, **—**는 시간 미확인입니다.

현재 과제 수치는 `draft-v1` 예비 명세이며 기본 결과는 **Pilot**입니다. 고정 명령의 작업 시간에는 Worker·CLI 시작, 실행 파일 해시 검사, 명령·출력·대상 재확인을 포함합니다. 준비·최종 검증·정리는 별도 기록합니다. AI 제작은 첫 지시부터 마지막 검증까지의 시간을 기록합니다. 두 모드의 시간을 하나의 점수로 합치지 않습니다.

독립 시행별 성공·실패·중단과 평균·중앙값·범위를 함께 확인하세요. 실패한 시행은 성공 시간 표본에서 제외합니다. 시간 표본이 적어도 승자를 자동 선정하지 않습니다. OS 캐시·발열·네트워크·외부 제공자의 상태까지 완전히 고립하지는 않습니다. AI 토큰은 제공자가 보고한 값만 기록하며 미제공은 빈 값입니다. 호출 한도는 이벤트를 관측한 시점에 중단하므로 이미 시작한 호출과 비용을 되돌리지 않습니다.

## 중단·기록·복구

- 탭 전환과 앱 최소화는 실행을 중단하지 않습니다. 실행 중인 도구는 탭에 표시됩니다. 벤치는 아래 **실행 중단**, 다른 도구는 **이 도구의 실행 중단**을 사용하세요. 앱 종료는 진행 중 작업의 중단과 정리를 기다립니다.
- 벤치는 **3 결과**, 다른 도구는 **실행 기록**에서 상세·실패 원인을 확인합니다. 결과 내보내기는 계획·환경·원시 JSON·CSV를 새 폴더에 저장합니다.
- 비정상 종료 후 **미완료 기록 확인**을 누르면 감독자가 끝난 기록을 중단 기록으로 표시합니다. 작업을 자동 재개하거나 기존 복제본을 새 시험으로 재사용하지 않습니다. 오래된 초기 시험 기록도 읽고 내보낼 수 있습니다.
- 설정·초안·보관함·기록의 기본 위치는 `%LOCALAPPDATA%\UnityBridgeDesk`입니다. 이 폴더를 없애면 설치된 프로젝트가 참조하는 관리 Connector도 사라질 수 있습니다. 목록 제거는 원본 파일 삭제가 아닙니다.
- 로그의 알려진 인증 문자열을 가리고 인증 파일은 내보내기에서 제외합니다. AI가 출력한 임의의 내용까지 완전한 비밀 제거를 보증하지 않으므로 공유 전에는 내용을 검토하세요.

다른 로컬 `file:` 패키지를 참조하는 프로젝트는 현재 벤치 복제에서 거부합니다. 임베디드 패키지 또는 고정 버전으로 준비하세요. 프로젝트·Editor 버전 불일치, 누락·변경된 CLI, 컴파일 오류, 오래된 연결, 잘못된 JSON은 성공으로 처리하지 않습니다. 실패 상세와 실행 폴더의 `editor.log`를 확인하세요.

## 작업실

상단 왼쪽 **도구 · 현재 이름 ⌄**에 포인터를 올리면 **설치·관리 / AI 작업 / 벤치마크 선택 패널만 아래로 내려옵니다.** 버튼을 선택하면 도구가 바뀌고 선택 패널은 접힙니다. 선택하지 않고 벗어나도 잠시 뒤 접힙니다. 작업 화면은 계속 보이고 위치와 크기도 유지됩니다. 클릭·키보드로 선택 패널을 열 수도 있습니다.

작업 화면은 선택한 도구가 영역 전체를 고정해서 사용합니다. 이동 손잡이·영역 채우기는 제거했으며 이전 이동 위치는 적용하지 않습니다. 도구를 전환해도 입력과 결과 화면이 유지됩니다. 선택 패널 밖의 작업 영역을 클릭하면 메뉴만 닫히며, 도구 선택 후 키보드 초점은 작업 입력으로 이동합니다.

설치·관리의 **설치 구성 열기**, AI 작업의 **AI 실행 구성**은 초안 화면 하단에 있습니다. 세 도구의 확인·시작 버튼은 실행 화면 하단에 고정되어 스크롤해도 보입니다. **구성 확인**을 통과하면 **설치 시작 / AI 작업 시작 / N개 시행 시작**으로 바뀌며 한 번 더 눌러야 실행됩니다. 중단 버튼은 실행 중에만 표시합니다. 설치·AI의 기록 목록과 상세는 각 영역에서 스크롤합니다.
