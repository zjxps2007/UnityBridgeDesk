# UnityBridge Desk v0.5.0 · 속도·안정성 벤치

UI·UX 개편과 고양이 아라·여우 아샤, 신뢰구간·반복 설계 기능을 통합한 정식 배포본입니다. [전체 릴리스 설명](docs/releases/v0.5.0.md)

ZIP을 모두 압축 해제한 뒤 루트의 **UnityBridge Desk 실행.exe**를 실행하세요. `app` 폴더를 옆에 유지하세요.

1. 준비 탭에서 자동으로 찾은 Unity를 확인합니다.
2. 비교할 정식·RC 릴리스 두 개 이상을 선택합니다. 공식 Unity 비교는 **공식 Unity CLI + Pipeline 함께 비교**를 켜고 UnityBridge 릴리스를 한 개 이상 선택합니다.
3. 연결만 확인할 때는 기본값을 사용합니다. 반복 설계에는 **반복 설계용 예비 설정**(새 프로젝트 20회·사전 실행 5회·측정 20회)을 선택하고 예정 시행 수를 확인한 뒤 **벤치 시작**을 누릅니다.
4. 완료 후 결과 확인을 누릅니다. 평균 차이와 감소율 95% 구간을 함께 읽습니다. **기준 버전 대비 → 측정 신뢰도와 다음 실험**에서 다음 반복 수를 준비하고, **시행 상세 → 호출 순서**에서 변동을 확인합니다. 내보내기에서 TXT·Excel·SVG·결과 폴더를 엽니다. `04_측정근거.txt`에 논문·수식·전제가 기록됩니다. [통계 방법과 한계](docs/STATISTICAL-METHODOLOGY.md)

좌측 목록은 준비 화면의 설정 목차, 진행 중 시행 검색, 결과의 실험·조건·시행 탐색을 제공합니다. 좁은 창에서 접힌 목록은 **목록** 또는 `Alt+0`으로 펼칩니다. `Alt+1·2·3`으로 준비·진행·결과를 전환합니다. 과거 결과는 좌측 **실행 기록**에서 고릅니다.

측정할 작업에서 **F04 exec**, **S01 명령 부하**를 선택할 수 있습니다. S01은 기본 요청 32개·동시 4개이며 부하 설정에서 바꿉니다. [명령 입력 예시와 설계 범위](docs/STABILITY.md)를 참고하세요. 결과에서 시간·유효 완료율 그래프와 안정성 요약을 확인하고 보고서 폴더의 SVG를 공유할 수 있습니다.

설치·활성화된 Unity Editor가 필요합니다. 다른 위치는 실행 파일 선택으로 지정할 수 있습니다. 가상머신·ISO·BIOS 변경·별도 Windows 계정 없이 실행하며 .NET 런타임은 포함돼 있습니다.

**공식 Unity CLI + Pipeline 비교**도 앱의 **벤치 시작** 버튼으로 실행합니다. Unity 6가 필요하며 CLI·Pipeline 파일은 자동으로 준비합니다. 버전 지정은 선택 사항입니다. 종료 후 같은 결과 화면에서 확인하고 설정을 재사용할 수 있습니다. [앱 사용법과 비교 근거](docs/OFFICIAL-UNITY-COMPARISON.md)에 측정 범위를 정리했습니다. `app/Compare-OfficialUnity.ps1`은 별도 자동화가 필요할 때만 사용합니다.

공식 도구는 앱 전용 하위 임시 폴더에서만 사용하고 벤치 종료·오류·취소 시 다운로드 원본까지 삭제합니다. 다음 벤치에는 인터넷 연결이 필요합니다. 준비·삭제 시간은 속도 측정에서 제외하며 결과에는 삭제 확인 여부를 남깁니다.

**Go unity-cli 함께 비교 · 비공식**으로 youngwoocho02/unity-cli도 추가할 수 있습니다. 기본 선택은 `0.4.1`이며 Unity 6를 사용합니다. CLI·Connector와 필요한 Test Framework·NUnit·Newtonsoft JSON의 준비·검증·정리는 자동입니다. Unity 6000.3.23f1에서 Go v0.4.1과 UnityBridge v0.3.0-rc.1의 실제 연동 30개 시행을 통과했습니다. [Go 비교 범위와 제한](docs/GO-UNITY-COMPARISON.md)을 확인하세요.

실험마다 새 프로젝트와 임시 폴더를 준비하고 Unity·CLI를 새로 실행합니다. 종료 시 시험 프로세스와 폴더를 정리합니다. Windows 사용자 설정·공용 서비스·시스템 캐시는 공유하며 보안 샌드박스가 아닙니다.
