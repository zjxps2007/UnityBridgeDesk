# 좌측 인덱스와 UI 개편 참고 문서

> 이전 개편의 참고 기록이다. 큰 시계·우측 위젯을 유지한다는 아래 내용은 이후 정보 중심 개편으로 변경되었다. 현재 화면은 [UI-NAVIGATION.md](../docs/UI-NAVIGATION.md), 이후 디자인 작업 방식은 [UI-DESIGN-WORKFLOW.md](UI-DESIGN-WORKFLOW.md)를 따른다.

확인일 및 적용일: 2026-09-18. 아래 방향을 기존 WPF 화면에 적용했다. 외부 UI 라이브러리나 스킬 패키지는 추가하지 않았다.

## 적용 목표

파스텔 배경과 연보라·로즈·민트 색상톤, 큰 시계, 구름 고양이를 유지한다. 좌측에는 실험·조건·시행을 찾는 목록을 두고, 중앙에는 선택한 작업과 결과를 크게 표시한다. 우측은 현재처럼 시간·진행·최근 알림을 맡는다. 기존 준비·진행·결과의 작업 흐름을 유지하면서 각 화면 안의 탐색 구조를 정리한다.

## 권장 정보 구조

`F01~S01`은 실험 종류이고 `#39`는 한 번의 실제 시행 번호이다. 서로 다른 단위를 같은 메뉴 수준에 섞지 않는다.

| 위치 | 역할 |
|---|---|
| 상단 | 준비·진행·결과 전환과 현재 실행의 이름 |
| 좌측 상단 | 현재 화면에서 사용할 탐색 항목과 검색 |
| 좌측 본문 | 실험 → 조건 목록, 선택한 조건의 시행 번호 목록 |
| 중앙 | 준비 폼, 진행 상태 또는 선택한 조건의 그래프·비교·시행 상세 |
| 우측 | 큰 시계, 현재 단계·완료 수, 최근 알림, 마스코트 |

좌측의 내용은 화면의 목적에 맞게 바꾼다.

- 준비: 비교 대상 / 실험 선택 / 실행 조건 / 환경 확인으로 이동한다.
- 진행: 전체 / 진행 중 / 실패 필터와 시행 목록을 제공한다.
- 결과: 실행 기록 선택, F01~S01 및 조건 선택, 해당 조건의 시행 목록을 제공한다.

결과 화면에서는 실험·조건을 선택하면 중앙의 그래프와 비교 표가 함께 바뀐다. 개별 시행을 선택하면 같은 중앙 영역에서 해당 시행의 상세를 보여준다. 조건별 시간·기준 버전 대비·시행 상세는 중앙의 보기 전환으로 유지하여 좌측 탐색과 역할이 겹치지 않게 한다.

시행 목록의 행은 `#39 · Go v0.4.1 · 성공`처럼 번호·대상·상태를 표시한다. 정렬·필터를 바꿔도 원래 시행 번호는 유지한다. 수백 개를 모두 펼치지 않고 현재 조건의 목록과 검색을 사용한다. 선택한 시행을 보고 있을 때 새 결과가 추가되어도 화면이 임의로 이동하지 않게 한다. 목록 선택은 조회 동작이며 벤치를 시작하거나 다시 실행하지 않는다.

## 디자인 방향 — 프로젝트에 맞춘 제안

다음 값과 배치는 외부 문서의 의무 규격이 아니라 현재 Desk에 맞춘 시작안이다.

- 좌측 펼침 폭은 약 216 DIP에서 검토하고, 중앙은 창 크기에 따라 확장한다. 좁은 창에서는 좌측 접기 기능을 제공하며 큰 시계는 유지한다.
- 현재 Palette의 `Line`, `Accent`, `AccentInk`, `Tint` 리소스를 재사용한다. 연보라는 각각 `#D7CBE4`, `#DCCCF1`, `#584278`, `#F0E9F8`이다.
- 선택 항목은 연한 보라색 면과 명확한 표시선으로 구분한다. 마우스 호버와 키보드 포커스는 선택 상태와 구별한다.
- 작은 상자 여러 개보다 정렬된 행, 얇은 구분선, 제목과 수치의 크기 차이로 정보를 묶는다. 버튼·입력칸의 높이와 간격을 통일한다.
- 실행 중·성공·실패는 색과 함께 글자 또는 아이콘으로 구분한다. 파스텔톤을 유지하되 본문과 수치는 충분히 진하게 표시한다.
- 마우스를 올렸을 때와 선택·펼침 동작에만 짧은 반응을 준다. 마스코트의 글로우와 이동 가능한 패널은 다시 추가하지 않는다.
- 긴 시행 목록은 WPF의 목록 가상화를 유지한다. 좌측 목록과 중앙 결과는 각자의 영역에서 스크롤하며, 한 영역 안에 불필요한 중첩 스크롤을 만들지 않는다.

## 적용 위치와 확인할 사항

주요 구현 위치는 `src/UnityBridgeDesk.Desktop/SpeedBenchWindow.xaml`, `.Navigation.cs`, 관련 Presentation·Interactions 코드와 `Themes/BenchNavigation.xaml`이다. 기존 BenchControls를 재사용하고 Palette의 색상 및 마스코트·배경 자산을 유지한다. 계측은 기존 SpeedBench 서비스가 담당하며, 화면 진행 메시지에 시행 계획과 완료 판정을 추가해 목록에 전달한다. 시간 집계·성공 판정·정리 규칙은 변경하지 않는다.

구현 시에는 실험·조건·시행 선택의 동기화, 필터 후 번호 보존, 진행 중 다른 시행 조회, 키보드 조작, 긴 목록과 작은 창·확대 배율에서의 잘림을 확인한다. 그래프와 비교 표의 대상 순서, 과거 결과 읽기, 보고서 내보내기와 중단 동작도 기존대로 유지되는지 확인한다.
