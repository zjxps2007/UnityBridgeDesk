# 모션 적용 기준 · 2026-09-19

앞서 원문을 읽은 frontend-design의 내용 중심 구성·절제된 움직임과 UI/UX Pro Max의 입력 피드백·포커스·움직임 축소 원칙을 UI-DESIGN-WORKFLOW.md, UI-NAVIGATION.md, MOTION.md, DEVELOPMENT.md와 조합한다. 외부 스킬을 새로 설치하거나 검색 스크립트를 실행한 것은 아니다.

## 적용할 동작

- 준비·진행·결과: 선택 밑줄이 같은 선 위에서 이동한다. 내용은 선택 방향을 따라 짧게 이동하며 나타난다. 탭 이름이나 클릭 영역 자체는 움직이지 않는다.
- 결과 보기·좌측 탐색: 사용자가 고른 내용만 짧게 전환한다. 선택·필터·스크롤 복원과 키보드 입력은 즉시 처리한다.
- 버튼·선택 행: 배경의 강조가 부드럽게 바뀐다. 버튼만 작은 눌림 효과를 주고 긴 목록 행과 텍스트 전체를 축소하지 않는다.
- 펼침·드롭다운·내보내기 메뉴: 화살표 회전과 짧은 내용 등장으로 열림을 표현한다. 닫기는 조작을 지연하지 않으며 펼침의 높이를 매 프레임 바꾸지 않는다.

짧은 반응은 약 90~160ms, 내용과 선택 위치 이동은 약 180~220ms로 통일한다. 끝에서 감속하는 이징을 사용하고 튕김·반복 재생·순차 등장 효과는 넣지 않는다. 빠른 재입력은 현재 위치에서 새 목표로 이어지고 효과를 대기열에 쌓지 않는다.

## 경계

마우스 휠·스크롤 막대·텍스트 입력은 기본 조작을 유지한다. 그래프 수치·막대 높이·진행 값은 즉시 실제 값을 표시한다. 별도의 부하가 되는 장식 반복 타이머를 추가하지 않는다. 기존 작은 마스코트는 기존 동작을 유지한다.

앱의 움직임 끄기, Windows 애니메이션 설정, 벤치 실행, 비활성화·최소화·종료 시 효과를 중지하고 최종 상태로 맞춘다. 팝업도 같은 조건을 적용한다. 코드 변경은 Desktop에 한정하며 측정·정리·통계 로직을 변경하지 않는다.

## 구현과 검증

DeskMotion의 공통 이징·불투명도·회전·이동을 스타일에서 사용한다. 공유 테마 브러시는 애니메이션하지 않고 각 컨트롤의 강조 면을 투명도로 바꾼다. 탭 표시는 DeskTabMotion의 한 개 밑줄이며 선택 이벤트와 배치 변경에만 목표를 갱신한다. 별도의 반복 타이머는 추가하지 않았다.

탭 내용 교체가 끝난 뒤 짧은 전환을 시작한다. 대기 중 다시 선택하거나 벤치를 시작하면 이전 예약을 취소한다. 멈춘 애니메이션 시계가 남았다는 이유로 다음 전환을 생략하지 않도록 실제 표시 값과 기준 값을 비교한다. 팝업은 소유 창의 Allowed 값을 바인딩하여 측정 시작과 움직임 끄기를 함께 따른다. 결과 표는 동일한 픽셀 너비·높이를 반복 지정하지 않도록 했다.

기존 렌더 검사에 선택 밑줄의 중간 위치와 방향 반전, 움직임 끄기 시 최종 위치, 반복 조작 후 복귀, 화면에서 제거된 강조 면의 시계 해제, 정지한 페이지의 재전환, 실제 창에서 준비에서 결과로 이동할 때 배치 완료를 확인하는 검사를 추가했다. 작은 창과 100·150·200% 렌더링, 메뉴·스크롤·키보드와 벤치 실행 시 정지는 기존 검사로 함께 확인한다.

화면 검토는 별도 데이터 경로의 WPF 창에서 기존 완료 기록을 읽어 수행한다. 앱의 환경 검색·실험 시작 핸들러는 실행하지 않는다. 전체 화면의 정적 확인과 선택 전환 프레임을 구분하며 캡처를 FPS 벤치 결과로 취급하지 않는다.

최종 Desktop 검사 28개가 통과했고, 테스트의 완료 대기 조건을 다듬은 뒤 WPF 렌더 검사도 다시 통과했다. 빌드 경고·오류와 테스트 종료의 처리되지 않은 예외는 없었다. 1100×740 실제 WPF 창에서 준비·진행·결과·조건 그래프·기준 비교를 오가며 확인했다. 탭 표시의 112개 프레임을 `docs/images/ui-motion.gif`로 저장했다. Core·Infrastructure 코드는 수정하지 않았고 이번 UI 변경을 위해 성능 실험을 새로 실행하지 않았다.
