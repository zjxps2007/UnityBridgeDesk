# 벤치마크 구성과 결과 해석

고정 명령과 AI 제작을 각각 켜거나 함께 측정할 수 있습니다. 두 방식은 결과를 구분하며 하나의 종합 점수로 합치지 않습니다. 현재 실험 수치와 판정 규칙은 `draft-v1` 예비 명세이고 결과는 Pilot입니다.

## 첫 시험

1. 벤치마크 준비 화면에서 **F01 응답 시험 선택**을 누릅니다. 고정 명령·F01·독립 반복 2회·준비 호출 1회·준비 후 측정 호출 3회가 설정됩니다.
2. **실험 환경 자동 준비**를 누르면 0.2.0·0.2.1 CLI·Connector를 검색하거나 공식 파일을 받아 검증·보관·등록합니다. 두 버전을 함께 선택하고 설치된 Editor를 연결합니다.
3. 프로젝트가 여러 개이거나 필요한 Editor가 없으면 카드의 안내를 완료합니다. 다른 버전은 기존 보관함 등록을 사용합니다.
4. 준비 완료 후 **N개 시행 시작**을 누릅니다. 직접 조건을 바꿨다면 **구성 확인**을 먼저 누릅니다. 두 버전이면 2조건 × 2버전 × 독립 2회 = 8개 시행입니다.
5. 결과에서 성공 여부, 조건별 시간, 표본 수 순서로 확인합니다.

자동 준비의 다운로드·보관·등록은 명령 측정 전에 끝납니다. 실제 프로젝트 복제·Connector 적용·Unity 기동은 시행 시작 후 수행하고 준비 시간으로 기록합니다. 명령별 시간 측정 범위는 바뀌지 않습니다.

## 무엇을 실행하나요?

| 실험 | 동일하게 수행하는 작업 | 정확성 검사 |
|---|---|---|
| F01 응답 | 작은 명령을 최초·준비 호출 이후 조건으로 실행 | 요청 표식, 프로젝트·프로세스, 응답 값 |
| F02 명령 분할 | 총 1,000개 이동 작업을 1·10·100회로 분할 | 전체 ID·개수·최종 위치 |
| F03 응답 크기 | 1 KiB·64 KiB·1 MiB ASCII 응답 | 길이와 모든 문자, 잘림 여부 |
| F04 코드 복귀 | 준비 상태 조회 / 코드 변경·컴파일 후 조회 | 새 리비전의 실제 실행 응답 |
| F05 Play / Stop | Play 진입과 Stop 복귀 | 실제 Play/Edit 상태와 후속 응답 |
| A01 낙하 장면 | 바닥·큐브·카메라 제작 | 저장·재열기, 실제 낙하·안정 |
| A02 프리팹 | 100개 생성, 20개 예외, 공통 변경 | 연결·격자·예외 보존·변경 전파 |
| A03 물리 도구 | 16개 큐브의 시작·초기화·접촉 집계와 일시정지·재개 | 버튼 입력에 따른 상태·집계·반복 실행 |

## 시간을 어떻게 재나요?

환경 준비, 작업, 최종 검증, 정리를 별도 구간으로 저장합니다. 환경 준비는 프로젝트 복제와 Unity 기동·컴파일을 포함합니다.

고정 명령의 작업 시간은 **호출 요청부터 출력 수집과 대상 재확인까지**입니다. CLI 프로세스 시작, 실행 파일 해시 검사, Connector 처리, 출력 변환 등이 포함됩니다. 순수 네트워크 시간이나 Unity 내부 처리 시간만을 뜻하지 않습니다.

AI 과제는 첫 지시부터 마지막 검증까지의 전체 시간과 AI·검증 구간을 함께 기록합니다. 토큰은 제공자가 보고한 값만 기록하고 미제공은 빈 값으로 남깁니다. 추정 비용은 만들지 않습니다.

### F01 첫 호출의 의미

**Unity 준비 후 첫 명령**은 Unity 기동·컴파일이 완료된 뒤 첫 측정 명령입니다. 프로젝트 생성부터 첫 명령까지의 시간이 아닙니다.

화면 단위는 **ms/호출**입니다. 준비 후 조건은 시행 안의 측정 호출을 평균 낸 다음, 독립 시행끼리 비교합니다. 원시 CSV의 `workMs`는 측정 호출 시간의 합계이므로 화면 평균과 직접 비교하지 않습니다. 별도로 기록한 환경 준비 시간과도 구분합니다.

## 고립과 비교 조건

- 실험·조건·독립 반복마다 새 프로젝트 복제본과 새 Unity 프로세스를 사용합니다.
- AI 과제는 별도 홈과 새 대화에서 실행합니다. 같은 작업의 후속 지시만 대화를 이어갑니다.
- 실행 전에 프로젝트 지문과 파일 해시·버전을 확인하고 계획을 고정합니다.
- CLI 전용 비교는 동일 해시의 Connector로 조건을 고정합니다. CLI + Connector 비교는 조합 전체의 차이를 측정합니다.
- 버전 순서를 교대할 수 있습니다. 실패한 복제본 보관 여부도 지정할 수 있습니다.

프로세스와 작업 파일을 분리해도 OS 캐시, 발열, 네트워크, 외부 AI 서비스 상태까지 완전히 고립하지는 않습니다. 현재 환경 복제는 다른 로컬 `file:` 패키지를 참조하는 프로젝트를 거부합니다.

## 결과를 읽는 순서

1. 전체 시도와 성공·실패·중단 수를 확인합니다.
2. 같은 계획·명세·실험·조건의 버전별 값을 비교합니다.
3. 성공한 **독립 시행**의 평균·중앙값·최솟값·최댓값과 표본 수를 확인합니다.
4. 실패한 시행은 원시 기록과 오류 상세로 원인을 확인합니다.

한 세션 안의 호출 여러 개를 독립 표본으로 세지 않습니다. 실패 시간을 성공 시간 표본에 섞지 않습니다. 모르는 시간은 0 대신 **—**입니다. 다른 실행 계획·명세·모드·릴리스 ID의 결과를 임의로 합치지 않습니다.

반복 2회는 흐름을 확인하기 위한 작은 표본입니다. 앱은 종합 승자나 점수를 자동으로 판정하지 않습니다. 자동 테스트 통과 개수도 성능 측정 표본 수와 다릅니다. 실제 생성형 AI 서비스 연결 시험은 아직 수행하지 않았습니다.
