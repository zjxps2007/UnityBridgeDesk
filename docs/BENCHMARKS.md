# 로컬 측정 명세

현재 스키마: `local-cli-completion-v1-pilot`.

## 측정 경계

게스트 OS 대신 이 PC에서 실행합니다. 고해상도 단조 시계로 **CLI Process.Start 직전부터 프로세스 종료와 stdout/stderr 수집 완료까지** 측정합니다. 응답 JSON 파싱과 값 검증은 측정 후 수행합니다. Worker 실행, CLI 도움말·지원 옵션 확인, 릴리스 다운로드·압축 해제·복사·해시 검사, Unity 기동·컴파일·ready 대기, 고정 500ms 안정화 대기, 파일 정리는 시간 표본에 포함하지 않습니다.

정식 EXE의 자체 런타임 추출처럼 CLI 실행 자체에서 발생하는 처리는 포함됩니다. RC 배포 ZIP은 준비 단계에서 한 번 풀고 그 런타임 전체를 사용합니다.

## F01 / F02 / F03

| 실험 | 입력 | 성공 검증 | 대표 시간 |
|---|---|---|---|
| F01 first | Unity ready 이후 준비 호출 없이 echo 1회 | 값 42, nonce, PID, 프로젝트 | 첫 명령 완료 시간 |
| F01 prepared | W회 echo 이후 M회 echo | 각 응답의 값·식별자·대상 | 반복 명령 평균 시간 |
| F02 | 오브젝트 1,000개 준비 후 이동을 1/10/100개 명령으로 분할 | 처리 수와 최종 오브젝트 ID·위치 | 첫 명령 시작부터 마지막 응답 수집까지 |
| F03 | 반복 패턴 ASCII 본문 1,024/65,536/1,048,576자 | 본문 전체와 요청·대상 | 반복 명령 평균 시간 |

F01~F03은 AI를 통하지 않고 고정된 `call desk_probe --params ...`를 보냅니다. CLI에 프로젝트·포트·응답 형식을 명시하며, --no-update-check는 해당 CLI가 지원하는 경우에만 넣습니다. Unity 실행 전에 --help와 call --help를 확인하며 F04는 exec --help도 확인합니다. 필수 기능이 없으면 동일 실험으로 측정하지 않고 벤치 호환성 오류로 기록합니다. 실제 인수는 결과에 남깁니다.

## F04 / S01

F04는 고정 C# 파일을 `exec --file` 또는 동일 의미의 `--code-file`로 실행하며 첫 명령과 반복 평균을 별도 프로젝트에서 측정한다. 지원 옵션은 도움말로 확인한다. 반환값·nonce·PID·프로젝트 경로를 검증한다. exec 요청 내부의 C# 컴파일은 시간에 포함된다.

S01은 명령별 요청 수와 동시 요청 수를 고정한다. 각 CLI의 완료 시간과 호출 판정을 기록하며 한 요청이라도 실패하거나 최종 Editor 상태·정리가 맞지 않으면 시행 전체를 시간 비교에서 제외한다. 부하 구간의 처리량, 성공 호출 P95와 시행 완료율도 표시한다. 입력 예시·실패 처리·분모·한계는 [STABILITY.md](STABILITY.md)에 정의한다.

## 반복과 해석

조건별로 새 프로젝트·프로세스를 준비하고 버전의 시작 위치를 회전하며 시드로 그 회전 순서를 정합니다. 반복 수가 버전 수의 배수일 때 실행 위치별 횟수가 같으며, 그 외에는 완전히 균형 잡힌 순서가 아닙니다. 실험 조건 순서 자체는 고정입니다. 시행 내 반복 호출을 독립 표본으로 세지 않습니다. 재실행한 시행도 같은 OS 캐시를 공유하므로 완전한 통계적 독립성을 보장하지 않습니다.

첫 명령 완료 시간은 **새 Unity가 준비된 뒤 보내는 첫 Bridge 명령**입니다. 프로젝트 생성 순간부터의 시간이 아니며, Windows나 물리 디스크 캐시가 비어 있다는 뜻도 아닙니다. 준비 중 파일 복사·해시 검사·CLI 도움말 실행도 시스템 캐시에 영향을 줍니다. CLI 자체를 한 번도 실행하지 않은 조건이 아니라, 측정 대상 Unity에 명령을 아직 보내지 않은 조건입니다. 반복 평균은 다른 새 프로젝트에서 W회 사전 실행 뒤 M회 명령의 평균을 구합니다. W=0도 허용합니다.

실패·취소·정리 실패는 성공 통계에서 제외하고 원시 기록에 남깁니다. 같은 블록에서 두 버전 모두 성공하고 정리가 확인된 경우만 비교합니다. 시간 감소율은 `100 × (1 - 후보 평균 / 기준 평균)`입니다. 성공 쌍에 한정된 결과이므로 실패율·미수행 수와 함께 읽습니다. 성공 호출의 관찰 P95와 상위 시행 단위의 평균·쌍 시간비 95% 구간을 구분해 제공합니다. 5회 미만은 구간을 만들지 않으며 전체 우열 판정은 제공하지 않습니다. [논문을 적용한 수식·반복 설계](STATISTICAL-METHODOLOGY.md)

F02의 전체 작업 시간에는 명령 사이의 앱 실행 제어 간격도 포함됩니다. F03의 조건 크기는 ASCII 본문 크기이며 JSON 전체 크기가 아닙니다. CSV의 bytes는 수집된 stdout 문자열을 UTF-8로 인코딩했을 때의 크기로, 네트워크 전송량을 별도로 계측한 값이 아닙니다.

OS·Unity 버전·Editor 실행 파일 해시·논리 CPU 수·물리 메모리·시행 직전 메모리 상태와 파일 해시를 기록합니다. 발열, CPU 클럭, 외부 프로그램 부하를 완전히 통제하거나 자동으로 보정하지는 않습니다.

기존 VM 측정은 [VM-BENCHMARKS.md](VM-BENCHMARKS.md), 파일·프로세스 분리와 정리는 [LOCAL-BENCH.md](LOCAL-BENCH.md)를 참고하세요.

## 버전 호환성과 근거

v0.1.3은 call/exec를 지원하지만 --no-update-check를 지원하지 않는다. 같은 작업·입력·검증·시간 경계를 유지하고 CLI 표현만 지원 여부에 맞춘다. 미지원 기능을 다른 동작으로 대체해 동일 그래프에 섞지 않는다. [확인 근거와 기록 처리](CLI-COMPATIBILITY.md)를 참고한다.
