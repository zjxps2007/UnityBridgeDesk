# UnityBridge Desk v0.5.0 · UI·UX 개편과 근거 있는 벤치 분석

v0.4.0 이후 다듬어 온 화면·사용 흐름, 아라·아샤, 벤치마크 방법론을 **v0.5.0 정식 배포**로 통합했습니다. 기존 exec·부하 안정성 시험과 UnityBridge·공식 Unity CLI + Pipeline·Go unity-cli 비교도 함께 제공합니다.

## 정보 중심으로 정리한 UI·UX

- **좌측 탐색 + 중앙 작업면:** 준비·진행·결과 흐름을 유지하면서 실행 기록, 실험·조건·시행 번호를 빠르게 찾습니다. 번호 검색과 버전·상태 필터를 제공합니다.
- **결과 읽기:** 전체 조건 비교표에서 세로 그래프, 기준 버전 대비, 시행 상세로 이동합니다. 버전의 순서와 색을 일관되게 유지하고, 같은 창에서는 선택·필터·보기·스크롤을 복원합니다.
- **조작 정리:** 내보내기를 한 메뉴에 모으고 설정을 팝업으로 제공합니다. 기록의 조건을 준비로 불러올 수 있으며 자동으로 벤치를 시작하지 않습니다.
- **시각·반응:** 파스텔·연보라 색조와 풍경 배경 3종을 유지하며 배경 없는 일반 화면도 고를 수 있습니다. 시계·진행 상태는 작은 보조 요소로 두고, 반복적인 움직임을 줄였습니다.

## 고양이 아라와 여우 아샤

아라는 은보라색 고양이, 아샤는 아이스 블루 여우입니다. 설정에서 한 마리만 표시하거나 둘 다 표시·숨김 처리하고 탐색·활동량을 각각 조절합니다. 높은 곳을 선호하는 아라와 넓고 낮은 발판을 선호하는 아샤의 행동을 구분했습니다.

버튼·입력칸·화면에 보이는 글자 줄·그래프의 실제 위치로 발판을 계산합니다. 걷기·대기·점프·낙하를 다듬었으며, 끌어 놓으면 아래의 적합한 발판에 착지합니다. 벤치와 설정 팝업 중에는 숨고 정지합니다. 바탕화면 독립 앱 **리틀 모델 엔진은 별도 배포**이며 Desk와 자동 동기화하지 않습니다.

## 평균 차이에 불확실성까지 표시

[Kalibera·Jones의 Rigorous Benchmarking in Reasonable Time](https://kar.kent.ac.uk/33611/)을 참고해 다음을 적용했습니다.

- 같은 Unity 시행 안의 호출을 독립된 실험으로 세지 않고 **새 프로젝트 시행 단위**로 집계합니다.
- 평균 시간과 기준 대비 시간 감소율에 **95% 신뢰구간**을 표시합니다. 쌍 비교에는 같은 블록의 공분산을 포함한 Fieller 확장을 사용합니다.
- 유효 시행·쌍 5개 미만, 불안정한 구간, 미완료, 실패 제외와 순서 영향을 구분합니다. 구간이 0%를 포함하면 차이 방향이 불확실합니다. 5회가 충분한 정밀도를 보장하지는 않습니다.
- **반복 설계용 예비 설정**과 분산·비용에 따른 다음 실험의 반복 수 제안을 제공합니다. 실행 중 표본을 자동 추가하거나 원하는 결과에서 멈추지 않습니다.
- 사전 실행 시간은 측정 평균에서 제외해 별도로 기록하며, **호출 순서·시행 순서 그래프**로 추세를 확인합니다.

## 공유하기 쉬운 결과 파일

보고서 폴더에 `00_결과요약.txt`, `01_결과분석.xlsx`, `02_실패내역.txt`, `03_결과그래프.svg`, **`04_측정근거.txt`**를 제공합니다. Excel은 기존 다섯 시트에 측정신뢰도·반복설계·사전실행을 추가한 여덟 시트입니다. 근거 TXT에는 논문·수식·전제·조건별 구간·다음 실험 제안을 남깁니다.

기존 설정과 결과 기록을 계속 사용합니다. 원본 JSON을 다시 쓰지 않으며, 이전 기록에 없는 사전 실행 시간이나 호출 판정은 추정하지 않습니다. 과거 보고서는 새 형식의 별도 사본으로 생성합니다.

## 설치와 시작

1. 릴리스 첨부 파일 **UnityBridgeDesk-v0.5.0-win-x64.zip**을 내려받아 전체 압축을 풉니다.
2. **UnityBridge Desk 실행.exe**를 실행합니다. 옆의 `app` 폴더도 함께 둡니다.
3. 설치·활성화된 Unity와 비교 대상을 선택합니다. 공식·Go 비교에는 Unity 6가 필요합니다.
4. 연결 확인에는 기본 설정을 사용합니다. 반복 분석에는 **준비 → 반복 설계용 예비 설정**을 선택한 뒤 예정 시행 수를 확인하고 벤치를 시작합니다.
5. **결과 → 기준 버전 대비 → 측정 신뢰도와 다음 실험**에서 구간과 다음 계획을 확인합니다.

.NET 런타임을 포함하며 가상머신·ISO·별도 계정 설정은 필요하지 않습니다. GitHub가 자동 생성한 Source code ZIP은 실행 파일이 없는 소스입니다. 업데이트는 새 폴더에 압축을 풀어 사용하면 됩니다.

## 해석과 검증 범위

실패·미수행을 0ms로 넣지 않습니다. 구간은 해당 조건의 유효 자료와 독립성·분포 가정에 한정되며, 여러 조건 전체의 승자나 환경에 무관한 성능을 보장하지 않습니다. 공개 배포 바이너리를 비교하므로 재빌드 변동 계층은 추정하지 않습니다. Windows 공용 캐시·서비스·PC 부하는 공유합니다.

합성 자료로 통계 계산, 이전 기록 호환성, UI·입력·렌더링, 실행기·배포 파일을 검증합니다. 이번 버전 통합 과정에서 실제 Unity 벤치를 새로 실행한 결과는 없습니다. 자동 검사와 패키지 검증 결과는 [v0.5.0 검증 기록](../V050-VALIDATION.md)에 정리합니다.
