# UnityBridge Desk v0.3.0 · 속도 벤치 전용

UnityBridge Desk를 **UnityBridge 릴리스별 명령 속도를 비교하는 도구**로 정리한 정식 버전입니다. 설치된 Unity를 확인하고 비교할 버전을 선택한 뒤 **벤치 시작**을 누르면 파일 준비부터 측정·결과 저장·정리까지 이어집니다.

## 주요 변경

- **속도 벤치로 기능 축소:** 일반 설치·관리, AI 작업, VM 관리 화면을 기본 앱에서 제외했습니다. 벤치에 필요한 CLI·Connector 자동 준비는 유지합니다.
- **VM 없는 로컬 실행:** VirtualBox·ISO·BIOS 설정 없이 설치된 Unity를 자동 탐색합니다. 다른 위치의 Editor도 직접 지정할 수 있습니다.
- **정식·RC 비교:** 공식 릴리스의 CLI와 같은 태그 Connector를 준비하고 커밋·해시를 고정합니다. RC의 EXE+런타임 폴더 전체와 RC1 보고 버전 예외를 처리합니다.
- **세 가지 고정 실험:** F01 첫 호출/준비 후 호출, F02 동일 작업의 1·10·100개 명령 분할, F03 1 KiB·64 KiB·1 MiB 본문 응답을 측정합니다.
- **시행별 준비·정리:** 새 프로젝트·임시 경로·UPM 캐시를 사용하고, 시험 프로세스 종료와 폴더 정리를 확인합니다. 실패·중단·정리 실패를 결과에 남깁니다.
- **결과와 UI:** JSON·CSV, 성공·실패·미수행, 평균·중앙값과 동일 블록 비교를 제공합니다. 파스텔 테마·큰 시계·고정 탭을 유지하고 시작 버튼을 하단에 고정했습니다.
- **벤치 근거 문서화:** README에 측정 경계, 실험별 목적, 순서·반복 설계, 응답 검증, 공유 환경의 한계와 Microsoft·Unity·NIST 근거를 추가했습니다.

## 다운로드와 실행

1. 아래 Assets에서 **`UnityBridgeDesk-v0.3.0-win-x64.zip`**을 받습니다.
2. ZIP 전체를 압축 해제하고 **`UnityBridge Desk 실행.exe`**를 실행합니다. `app` 폴더를 함께 두세요.
3. Unity와 비교할 릴리스를 선택하고 **벤치 시작**을 누릅니다.
4. 결과 탭에서 성공 여부와 시간을 확인합니다.

Windows x64와 설치·활성화된 Unity가 필요합니다. .NET 런타임은 포함돼 있습니다. GitHub의 자동 **Source code ZIP**은 실행 파일이 없는 소스입니다. `SHA256SUMS.txt`로 첨부 ZIP의 해시를 확인할 수 있습니다.

## 확인한 범위

- 자동 검사 **170개 통과**.
- Unity **6000.3.23f1**에서 **18개 시행 성공**, 각 시행의 응답 검증·임시 폴더 정리 확인.
- F01은 0.2.0·0.2.1·0.2.2-rc.2, F02/F03은 0.2.1·0.2.2-rc.2로 확인했습니다.
- Unity 실행 중 중단했을 때 시험 프로세스 종료·정리와 후속 시행 중단을 확인했습니다.
- 실행용 ZIP 해시, 실행 파일 버전, 한글 경로로 옮긴 실행기의 대상·인수 전달을 검사했습니다.

실제 18개 시행은 기능 확인이며 버전 간 통계적 우열을 입증한 시험은 아닙니다.

## 결과의 범위와 기존 데이터

측정 대상은 **CLI + Connector 조합의 명령 완료 시간**입니다. 다운로드·Unity 기동·컴파일은 측정 밖이며 AI 성능, 게임 FPS, Connector 내부 처리만의 시간은 측정하지 않습니다.

파일·프로세스는 시행별로 분리하지만 Windows 사용자 설정·서비스·시스템 캐시는 공유합니다. 기본 실험은 예비 설정이며 신뢰구간·유의성 검정·전체 승자 판정은 제공하지 않습니다. 원시 결과에는 개인 경로가 포함될 수 있습니다.

이전 VM과 실행 기록은 보존합니다. 새 로컬 결과는 `speed/local-runs`에 `local-cli-completion-v1-pilot` 스키마로 저장해 이전 결과와 구분합니다. Desk의 **v0.3.0**과 비교 대상 UnityBridge 버전은 별개입니다.
