# 아샤의 발판 탐색 적용 판단

2026-09-19 · v0.4.0

후속 변경: 사용자가 화면에 보이는 각 줄과 버튼을 발판으로 요청해 [개별 요소 인식](ASHA-FINE-SURFACES.md)을 적용했다. 아래의 ‘명시한 면만 사용’은 초기 구현 기록이며 현재 기준은 후속 문서와 `ASHA.md`를 따른다.

사용자는 아샤가 고양이처럼 높은 곳을 찾고, 테두리·텍스트를 구조물로 삼아 스스로 올라가려 하기를 요청했다. 직전의 반응 절제는 앱 전체에 유지하고, 아샤의 목적지 선택과 행동 연결을 능동적으로 바꿨다.

## 조합한 지침

- [프로젝트 디자인 기준](../design/UI-DESIGN-WORKFLOW.md): 정보와 조작을 우선하고 실제 WPF 렌더링으로 검증한다.
- [frontend-design SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md): 새 장식 대신 아샤의 고유한 행동으로 캐릭터성을 드러낸다.
- [UI/UX Pro Max SKILL.md](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/SKILL.md)와 [quick-reference.md](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/references/quick-reference.md): 입력 방해를 피하고 움직임 끄기와 시스템 설정을 따른다.
- [아샤](ASHA.md), [모션](MOTION.md), [화면 구성](UI-NAVIGATION.md): 기존 설정·프레임·벤치 정지 조건을 보존한다.

외부 스킬 문서는 같은 날 앞선 작업에서 원문을 읽은 자료이며, 이번에는 관련 프로젝트 문서와 코드를 다시 확인했다. 외부 스킬을 설치하거나 검색 스크립트를 실행한 것은 아니다. 새 이미지를 만들지 않고 기존 프레임과 WPF 자세 변환을 사용했다.

## 선택한 구조와 범위

임의의 빈 픽셀을 걷던 지도 대신 명시한 수평 면의 연결 그래프를 만든다. 물리와 발판을 사용자가 따로 설정하지 않아도 된다. 입력칸·그래프·표 셀은 지형으로 전환하지 않는다. 실제 글자의 너비를 사용하며, 제목 위를 서 있을 수 있어도 이동 중 다른 내용을 통과할 수는 없다.

살피기·웅크림·점프·뛰어내리기·착지와 불가능한 곳에 앞발을 뻗는 반응을 연결했다. 최신 수정에서는 높이 선호가 방문 감점보다 커 가까운 두 발판만 왕복하던 원인을 없앴다. 구역별 방문 횟수와 실제 도착 순서, 최근 도착 지점의 주변까지 기억하고 아직 덜 탐색한 구역을 우선한다. 먼저 갈 수 있는 곳을 구하므로 미방문이라는 이유만으로 막힌 장소를 목표로 삼지 않는다. 발판이 작을 때는 가까운 이동을 허용한다.

앞서 제안한 동작 중 내려다보기·높이별 착지·귀와 꼬리 표현을 이번 우선 적용 범위로 삼았다. 안전한 출발 자리로 걸어가 아래를 살핀 뒤 낙차에 맞게 내려온다. 그림을 새로 만들지 않고 작은 연결 영역의 변형으로 귀·시선·꼬리를 움직인다. 발은 고정하고 새로운 타이머는 추가하지 않는다. 긴 휴식·자동 수면을 다시 넣지 않으며 입력 후 대기, 움직임 끄기와 벤치 중 정지를 보존한다.

내려오기는 올라가는 포물선의 재사용 대신 아래로 가속하는 경로와 별도의 자세로 표현했다. 출발점의 글자를 피할 때만 작은 도약을 더하고 전체 궤적을 검사한다. 디자인 지침의 입력 우선·명확한 행동 표현은 채택하되, 일반 화면에도 지속적인 모션을 확대하는 장식 예제는 적용하지 않는다. 연속 이동은 최신 요청에 따라 아샤에만 적용한다.

상단의 현재 실행 버튼은 내용 너비만 차지하도록 했다. 표시 문구와 동작은 그대로 두고 빈 배경 전체가 클릭 영역과 장애물로 남지 않게 했다. 테마·배경·시계·캐릭터 외형과 벤치 기능은 유지한다. 떠다니는 패널이나 새 위젯은 추가하지 않았다.

## 검증 범위

### 대기 모션 후속 개선

최신 요청에 따라 정지 그림에 가까웠던 idle에 상체 호흡과 간격을 둔 귀·꼬리·시선 반응을 추가했다. frontend-design의 캐릭터성을 드러내는 표현과 UI/UX Pro Max의 입력 우선·움직임 끄기 원칙을 기존 프로젝트 모션 기준에 맞췄다. 화면 전체를 흔들거나 몸 전체를 반복 확대하는 표현은 제외했다. 대기 진입은 현재 자세에서 이어지고, 대기 반응 때문에 산책을 늦추지 않는다.

같은 그림과 타이머를 사용하며 변형 도형·브러시를 재사용하도록 바꿨다. 발·머리·전체 크기를 고정하는 호흡, 반응 중첩 방지, 상태 전환 후 대기 일정 초기화를 검사한다. 실제 WPF 결과 화면에서 위치를 유지한 호흡·귀·꼬리·시선과 끄기 동작을 확인했다. 앞서 제안한 이동 개선 중 이번 idle에 직접 연결되는 걷기 구간의 대기 프레임 제거와 자세 연결을 함께 적용했다.

Desktop 검사 47개가 최종 통과했으며 빌드 경고·오류는 0개이다.

발판 모델 11개와 탐색·표현 검사 5개, 실제 WPF의 기존 화면·입력 검사에 자율 목적지 선택, 연속 이동 완료 3회 이상, 점프·하강 상태 연결, 하강 중 입력 후 착지와 대기, 발판 제거·좁은 창 복구를 포함했다. 세 가지 난수 조건에서 여러 구역으로 이동하는지 확인했다. 1440×850 결과 화면에서는 약 565 DIP의 좌우 이동과 아래를 살핀 뒤 내려오는 모습을 캡처하고, 960×660 창에서도 안전한 면 위에 있는지 확인했다. 영상의 시작 위치만 검토용으로 지정했으며 첫 대기를 포함한 행동·목적지·경로는 자율 로직이 선택했다. 실제 벤치나 유료 AI 호출은 하지 않았다.

벽을 붙잡는 전용 3D 모델이나 Live2D를 추가한 것은 아니다. 2D 그림과 발판 사이의 점프로 구현했다. 화면 구조상 연결되지 않은 곳은 갈 수 없으며, 빈 화면처럼 안전한 면이 없는 경우에도 공중을 바닥으로 삼지 않는다.
