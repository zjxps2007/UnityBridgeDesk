# VM 개발 미리보기 · 구현과 검증 상태

기준일: 2026-09-15. **첫 구현이며 실제 VirtualBox 게스트 Windows·Unity 통합 시험 전입니다.** 시험용 VM·Windows 설치 ISO가 준비되지 않은 상태에서 앱과 제어기·계측기의 독립 검증을 진행했습니다.

## 구현한 항목

| 구성 | 책임 |
|---|---|
| SpeedBenchWindow | 속도 벤치 전용 준비·진행·결과, 릴리스 선택, VM 안내, 설정 초기화와 되돌리기 |
| ReleaseRepository | 공식 릴리스 조회, 태그 커밋 고정, CLI·Connector 다운로드·검증·보관 |
| VirtualBoxHost | 전용 전체 복제·기준 스냅샷, 소유 확인, 설정·디스크 검증, 게스트 파일 전달·실행·네트워크 차단·복원 |
| SpeedCoordinator | 반복 계획, 시행 생명주기, 결과 식별 확인, 취소·실패 정리, 기록 저장 |
| SpeedGuest / TimedProcessRunner | 게스트 환경 확인, Unity 준비, 고정 명령 실행, 단조 시계 측정과 응답 검증 |
| SpeedAnalysis | 성공 시행 기술 통계, 같은 블록의 버전 비교, 실패·미수행 포함 CSV |

사용자가 준비한 VM을 전체 복제하고 하드웨어 식별자를 보존합니다. 전용 복제본은 같은 VM ID와 자원 설정을 사용합니다. 각 시행 전후 전원이 꺼진 기준 스냅샷으로 복원합니다. **복제 후 Unity 활성화가 유지되는지는 실제 환경에서 추가 확인해야 합니다.**

준비에만 NAT 연결을 허용하고 ready 이후 연결을 끊습니다. 호스트가 차단을 확인한 후 게스트에 측정 허가를 보냅니다. 호스트에 Unity를 실행하는 대체 경로는 새 UI에 없습니다.

## 자동 검사의 범위

2026-09-15 RC 설치 대응 후 로컬 자동 검사 **165개**(Core 38, Infrastructure 99, Desktop 28)가 통과했습니다. 빌드 경고·오류와 테스트 호스트 종료 예외는 없었습니다.

- 실제 Windows 자식 프로세스의 표준 출력·오류, 종료 코드, 시간 제한, 출력 제한, 취소와 사전 해시 거부
- 합성 VirtualBox 응답으로 전체 시행 순서·복원·요청 일치·네트워크 차단 후 허가·암호 파일 정리
- 다른 VM 소유 표식, 기준 디스크 변경, 복원 실패, 취소 중 정리와 다음 시행 중단
- 합성 릴리스 서버로 다운로드·해시·고정 커밋·보관본 재사용·변조 거부
- WPF의 세 탭·VM 미준비 안내·초기화 되돌리기·큰 시계·확대 화면 렌더링

**합성 VM 검사에서 사용하는 시간은 시험용 값입니다. 실제 UnityBridge 성능 자료가 아닙니다.** 공식 파일 준비 검사도 Unity 실행 호환성을 입증하지 않습니다. 자동 검사 수와 실행 증거는 개발 작업 기록에서 구분해 보고합니다.

별도 데이터 폴더에서 실제 공식 릴리스 목록 조회, **0.2.0·0.2.1 CLI와 Connector 다운로드**, 게시자 CLI 해시·기존 검토 커밋·Connector 내용 해시 대조, 네트워크를 거부하는 클라이언트로 보관본 재사용을 확인했습니다. 다운로드한 CLI·Unity는 실행하지 않았습니다.

RC 설치 대응에서는 **0.2.0·0.2.1·0.2.2-rc.1·0.2.2-rc.2**를 새 준비기로 받고, RC ZIP의 게시자 해시·런타임 전체 해시·전달 후 동일성·오프라인 재사용을 확인했습니다. 구버전의 기존 보관본도 재사용했습니다. RC1의 알려진 보고 버전 예외는 공식 커밋에 한정합니다. [변경 내용과 근거](RC-INSTALL.md)를 참고하세요.

## 실제 환경이 생긴 뒤 해야 할 검증

1. 설치된 VirtualBox의 실제 출력 형식, Guest Additions 파일 전송·명령 실행과 정상 종료 확인
2. 게스트 Unity 활성화·패키지 준비·ready·네트워크 차단 후 F01 응답 확인
3. 정상 종료와 강제 중단을 포함해 디스크·TEMP·프로필·레지스트리 오염 표식이 복원되는지 실험
4. 알려진 지연을 주입한 실제 게스트 타이머 확인, F02·F03 정확성, 같은 버전끼리의 A/A 예비 시험
5. 예비 변동 분석 후 W·N·M과 본시험 정밀도 결정

아직 추가 구현할 항목은 블록 단위 신뢰구간과 정식 판정 화면, 자동 익명화 내보내기, 호스트 부하·전원 상태 기록 확대입니다. [방법론](BENCHMARK-METHODOLOGY.md)의 목표 전체가 구현 완료된 것은 아닙니다.

## 현재 제약

- VirtualBox 한 종류, Windows x64 게스트, Unity Hub 기본 Editor 설치 위치를 사용합니다.
- OS·Editor 자동 설치와 Unity 로그인·활성화는 제공하지 않습니다.
- VM 전체 복제와 기준 디스크 해시 확인에 저장 공간과 준비 시간이 필요합니다.
- 게스트 계정 암호는 실행 중 임시 파일로 전달하고 정상 정리 시 삭제합니다. 호스트 강제 종료 시 잔여 파일 가능성이 있습니다.
- 결과 원본에는 개인 경로가 포함될 수 있습니다. 현재 폴더 열기는 자동 익명화 내보내기가 아닙니다.
- 다른 VirtualBox VM 실행을 검사하지만 다른 가상화 제품이나 일반 호스트 작업의 자원 경쟁까지 막지 않습니다.

VM 검증이 끝나기 전에는 기존 배포본을 덮어쓰지 않는 **별도 개발 미리보기**로 배포합니다.

## 구현 근거

VM 복제·스냅샷 복원·명령 실행·파일 전달·네트워크 제어에는 [Oracle VirtualBox 7.2 명령 참조](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/vboxmanage.html)를 사용했습니다. 이 문서에 맞춘 구현과 실제 설치 환경에서의 검증은 별개입니다. 실험 선택과 계측·통계 판단의 근거는 [방법론과 출처](BENCHMARK-METHODOLOGY.md)에 정리했습니다.
