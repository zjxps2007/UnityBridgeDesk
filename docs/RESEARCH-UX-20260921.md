# 연구 기능의 UI·UX 적용 기록

2026-09-21. v0.5.0 미배포 변경이다. 기존 파스텔·연보라, 배경, 좌측 탐색과 준비·진행·결과 구조를 유지한다. 추가 라이브러리나 상시 분석 프로세스를 설치하지 않는다.

## 해결한 동작

연구 목적이 접힌 설정 안에 있고 모든 목적에 A/A 허용 차이가 보였다. 진단이 끝나면 JSON 폴더만 열렸으며, 다음 검증과 새 세션을 준비하는 경로가 불분명했다.

실험 목적을 작업 설정 맨 위로 올린다. 탐색·예비·본시험·A/A·지연 감지를 구분하며 바로 아래에서 대상 수와 측정 의미를 안내한다. 본시험·검증을 선택하면 연구 계획을 펼친다. A/A 허용 차이는 해당 목적에서만 보이며 숨겨진 입력의 오류가 일반 비교를 막지 않는다. 사용자가 정해야 하는 연구 질문과 허용 차이의 근거를 임의로 채우지 않는다.

필수 입력 오류를 가까운 위치에 글로 표시하고, 기존 ‘확인할 항목으로’ 동작이 해당 입력을 펼쳐 포커스를 옮긴다. 정상 입력에서는 오류 행도 접힌다. 목적 변경은 실험 선택이나 반복 수를 몰래 바꾸지 않으며 실행 전에 전체 시행 수를 보여준다.

연구 묶음과 세션 메모는 선택 입력이다. 실행마다 고유 ID를 자동 생성한다. 실행 기록에서 연구 묶음·세션 ID로 검색할 수 있으며, 결과의 ‘같은 조건으로 새 세션 준비’는 이전 조건을 복원하고 세션 메모만 비운다. 준비만 하며 측정을 자동 시작하거나 기존 자료에 합산하지 않는다.

결과의 ‘시행 포함 범위·연구 기록’은 세션·계획 일치·파일 명세, 대상별 유효·실패/제외·중단·미수행을 함께 설명한다. 이 분모는 계획 전체이며 기존 S01 평가 완료율의 분모와 구분한다. 실패가 있으면 제외 사유 확인을 먼저 안내한다. 자료 저장은 기존 내보내기 메뉴에 둔다.

비Unity 진단은 드문 작업이므로 별도 펼침 영역에 둔다. 진행 횟수, 완료·중단, 잔차의 뜻, 실제 Unity 검증으로 이어지는 행동을 화면에 보여준다. 읽기용 `00_진단요약.txt` 버튼을 제공하며 JSON은 상세 근거로 남긴다.

## 검증과 한계

960×600·1440×850, 100·150% 연구 화면을 실제 WPF 렌더링으로 확인했다. 목적별 입력 노출, 질문·허용 차이 오류의 포커스 대상, 설정 왕복, 시작 조건을 검사한다. 전체 화면 검사에는 기존 100·150·200% 화면·스크롤·키보드·메뉴 검사도 포함된다.

이 기록은 구현 검토이다. 실제 사용자 대상 과제 수행 시간·오류율·설문 검증은 아직 하지 않았다. 후속 사용성 확인은 ‘A/A 준비’, ‘진단 결과 이해’, ‘제외 원인 찾기’, ‘새 세션 준비’, ‘연구 자료 저장’ 과제로 진행한다. 화면 변경과 함께 들어간 실행 순서·지연 대조·F02 정답 검사 변경은 [연구 검증 안내](RESEARCH-VALIDATION.md)에 별도 명세한다.
