# CLI 호환성 확인과 오류 해석

## v0.1.3에서 확인한 문제

이전 Desk는 모든 버전에 `--no-update-check`를 보냈다. v0.1.3은 이 옵션을 지원하지 않아 CLI가 종료 코드 2와 `unrecognized arguments: --no-update-check`를 반환했다. 따라서 해당 기록은 UnityBridge의 명령 처리 속도나 부하 안정성의 실패 사례로 해석할 수 없다.

확인 근거는 v0.1.3의 고정 커밋 `7df4378982b7e651e96addb7cd3642a521f7e731`의 [공식 CLI 구현](https://github.com/zjxps2007/UnityBridge/blob/7df4378982b7e651e96addb7cd3642a521f7e731/src/unity_bridge/cli.py)과 공식 Windows x64 실행 파일의 도움말이다. 실행 파일 SHA-256은 `83e80103c6dd5947831fed0913e942283f8c7eb10383ea55bdebe0b8165934b8`이다. 2026-09-18에 이 해시를 확인한 실행 파일의 `--help`, `exec --help`가 종료 코드 0으로 반환됨을 확인했다. call 및 exec 파일 입력은 존재하며 exec 도움말에는 `--code-file`과 별칭 `--file`이 함께 표시된다.

## 새 실행 순서

1. 전달한 CLI·런타임 해시와 폴더를 검증한다.
2. Unity 실행 전에 CLI `--help`, `call --help`를 확인한다. F04에서는 `exec --help`도 확인한다. 각각 최대 30초로 제한한다.
3. 프로젝트·포트·instances 경로·JSON 출력·시간 제한과 call JSON 입력 지원을 확인한다. `--no-update-check`는 지원할 때만 넣는다. exec는 지원하는 파일 입력 별칭을 선택한다.
4. 필수 기능이 없으면 벤치 호환성 오류로 종료한다. 다른 작업으로 바꿔 같은 조건으로 비교하지 않는다.
5. 이후 새 Unity를 준비하고 기존의 측정·응답 검증·정리를 수행한다. 대상·입력·작업량·시간 측정 경계는 유지한다.

이 확인은 UnityBridge 도구를 호출하지 않는다. 첫 명령 조건에 사전 Bridge 호출을 추가하지 않는다. 다만 CLI 실행과 파일 읽기는 시스템 캐시에 영향을 줄 수 있으므로 이 조건은 CLI 또는 OS 캐시가 차가운 상태를 뜻하지 않는다. CLI 도움말 시간은 명령 완료 시간에 포함하지 않고 준비 시간에 포함한다. 새 준비 절차와 구형 Desk의 결과를 같은 실험의 반복처럼 합치지 않는다.

실제 명령 인수는 결과에 기록한다. `cli-help.txt`, `cli-call-help.txt`, 필요한 경우 `cli-exec-help.txt`를 시행 증거 폴더에 보존한다. 도움말 확인만으로 해당 버전의 모든 Unity 명령이 정상 동작한다고 보장하지 않는다. 실행 시 미지원 응답은 별도로 기록한다.

## 기존 기록 처리

원본 JSON·CSV·오류 문자열·성공/실패 판정·시간은 변경하지 않는다. 미지원 `--no-update-check` 오류 원문이 명확하게 남은 기록만 화면과 새 보고서에서 벤치 호환성 오류로 설명한다. 시간 통계에는 계속 포함하지 않는다. 완료율은 환경 준비·벤치 호환성 오류를 평가 대상에서 분리하며 종료 건수·제외 건수도 함께 보존한다. 기존 보고서 파일은 덮어쓰지 않고 현재 보고서 형식의 새 사본을 만든다.

오류는 환경 준비 실패, 벤치 호환성 오류, 명령 실행 실패, 정리 실패로 구분한다. 미지원 명령도 호환성으로 분리하며, 원인을 알 수 없는 과거 오류를 임의로 호환성 문제라고 추정하지 않는다.
