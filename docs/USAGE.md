# 로컬 속도 벤치 사용 가이드

## 처음 실행

1. ZIP 전체의 압축을 풀고 `UnityBridge Desk 실행.exe`를 실행합니다.
2. 준비 탭에서 자동으로 찾은 **이 PC의 Unity**를 확인합니다. 여러 개면 목록에서 선택할 수 있습니다. 기본 설치 경로와 Unity Hub 기록, 이전에 선택한 위치를 탐색합니다.
3. **비교할 릴리스**에서 두 버전 이상 선택합니다. 첫 실행에는 공식 목록을 조회하며, RC는 직접 선택합니다. 이후 목록은 새로 확인 버튼으로 갱신합니다.
4. **벤치 시작**을 누릅니다. 선택한 파일 준비 버튼은 사전 다운로드용이며 필수 단계가 아닙니다.

Unity는 설치·활성화돼 있어야 합니다. 앱은 Unity 설치나 라이선스 로그인을 대신하지 않습니다. 가상머신, 별도 사용자 계정, 관리자 실행은 요구하지 않습니다. 회사 PC 등에서 Unity 실행이 제한되면 해당 정책에 따라 준비해야 합니다.

기존 개인 Unity 프로젝트를 지정하지 않습니다. 모든 실험은 앱이 만든 새 최소 프로젝트에서 수행합니다. CLI와 Connector는 버전별로 자동 보관하고 해시를 검사합니다. RC의 런타임 전체도 자동 준비합니다. [RC-INSTALL.md](RC-INSTALL.md)

## 실험 조건

- F01: 준비 후 첫 호출 / 준비 호출 이후 반복 호출.
- F02: 오브젝트 1,000개 이동을 1·10·100개 명령으로 분할.
- F03: 1 KiB·64 KiB·1 MiB 고정 본문 반환.
- F04: 같은 C# 파일을 exec로 처음 실행하거나 준비 호출 이후 실행.
- S01: 명령별 고부하·고밀도 요청. 기본 5개 시나리오, 요청 32개·동시 4개. 부하 설정에서 수치와 다른 명령을 지정할 수 있다. [입력 형식·근거·제한](STABILITY.md)
- 새 프로젝트 반복 N: 매번 Unity·프로젝트를 새로 준비하는 반복 수.
- 준비 호출 W: 측정 전에 실행하는 호출 수. F01·F04 첫 호출과 S01에는 적용하지 않습니다.
- 준비 후 측정 호출 M: 한 시행 안의 반복 호출 수. 별도 시행으로 세지 않습니다.

기본 F01, N=2, W=1, M=3에서 두 버전을 선택하면 8개 시행입니다. Unity 준비와 컴파일을 매 시행 반복하므로 시간이 걸립니다. 작은 예비 설정으로 통계적 승자를 판정하지 않습니다.

**벤치 설정 초기화**는 실험·횟수·시간 제한·시드를 기본값으로 돌립니다. Unity·버전 선택과 결과는 보존하며 직전 초기화는 되돌릴 수 있습니다.

## 진행과 중단

`새 실험 폴더 준비 → Unity 실행·컴파일 → 고정 명령 측정 → 결과 저장·프로세스 종료 → 폴더 정리`

진행 탭에서 현재 버전, 조건, 시행 순서와 단계를 봅니다. Unity 준비 시간은 CLI 속도에 포함하지 않습니다. 측정 중에는 다른 무거운 작업을 줄이면 비교 변동을 줄이는 데 도움이 됩니다.

중단 버튼을 누르거나 창을 닫으면 시험 프로세스 묶음을 종료하고 정리를 기다립니다. 원래 열려 있던 개인 Unity 프로세스를 찾아서 종료하지 않습니다. 폴더 삭제·프로세스 종료가 확인되지 않으면 다음 시행을 멈춥니다.

앱 프로세스가 강제 종료돼도 운영체제의 Job Object가 그 묶음의 프로세스를 종료하도록 구성했습니다. 남은 작업 폴더는 다음 벤치 시작 전에 소유권과 실행 상태를 확인해 정리합니다. 파일 잠금·전원 차단·공유 서비스 등 모든 상황의 무잔여를 보장하지는 않습니다. 소유 표식이 없거나 관련 프로세스가 살아 있으면 임의 삭제하지 않습니다.

## 결과 확인

1. 상단 메모의 **계획·기록·성공·실패·중단·정리 실패·미수행** 수를 확인합니다. **요약 메모 → TXT 열기**로 조건별 평균 시간 차이와 상세 수치를 읽고, **메모 복사**로 짧은 비교 설명만 복사합니다.
2. 같은 조건과 버전의 평균·중앙값을 확인합니다. 단위는 ms입니다.
   조건별 시간의 **그래프로 보기**에서 조건과 지표(평균 완료 시간 / 유효 완료율)를 바꿀 수 있습니다. 시행 상세의 **안정성 요약**에서 오류 종류·시간 변동·성공 호출 P95·부하 처리량을 확인합니다.
3. 버전 비교는 같은 블록에서 두 버전 모두 성공하고 정리가 확인된 경우만 사용합니다.
4. 시행 상세에서 실험·버전·상태를 고르고, 선택한 시행의 오류와 **임시 폴더 정리** 상태를 확인합니다. **이 시행의 로그 열기**로 해당 시행의 로그를 봅니다. 필터 초기화는 이 목록에만 적용됩니다.
5. **분석 Excel 열기**와 **자료 폴더 → 보고서 폴더**로 요약 TXT·분석 Excel·실패 내역·SVG 그래프을 확인합니다. 과거 기록도 재실험 없이 생성합니다.
6. JSON·CSV·전체 로그는 **자료 폴더 → 원본·로그 폴더**에서 엽니다. 이전 방식의 기록과 테마 변경은 오른쪽 위 **앱 관리**에 있습니다. [결과 파일의 구조와 읽는 기준](RESULTS.md)을 참고하세요.

원시 결과에는 실제 경로·컴퓨터 이름이 포함됩니다. 공개 전에 확인하세요. 실패를 0ms로 합산하지 않습니다. 폴더에 들어 있는 dump는 이름과 크기를 기록한 뒤 작업 폴더와 함께 정리하며, 원본 대용량 dump를 결과에 복사하지 않습니다. 전역 Windows 오류 보고 저장소는 건드리지 않습니다.

## 저장 위치

기본 루트: `%LOCALAPPDATA%/UnityBridgeDesk/speed`

| 위치 | 내용 |
|---|---|
| `local-settings.json` | Unity 선택, 실험 조건, 테마, 버전 선택 |
| `releases` | 정식·RC CLI와 Connector 보관함 |
| `local-work/<시행 ID>` | 임시 프로젝트·CLI 복사본·캐시·임시 파일. 완료 후 삭제 |
| `local-runs/<실행 ID>` | 결과 JSON·CSV, 요청 명세, 로그와 상태 기록 |
| `reports/<시작 시각·실행 ID>` | 읽기용 요약 TXT, 분석 Excel, 실패 내역. 원본에서 재생성 가능 |
| `runs`, `vms`, `settings.json` | 이전 VM 방식 자료. 보존하며 새 결과와 혼합하지 않음 |

현재 방식은 Windows 사용자 설정·시스템 캐시·공용 서비스를 공유합니다. TEMP/TMP 변경만으로 사용자 프로필이 격리됐다고 표시하지 않습니다. 상세 범위는 [LOCAL-BENCH.md](LOCAL-BENCH.md)를 참고하세요.
