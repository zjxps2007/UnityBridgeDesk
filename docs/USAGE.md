# 사용 가이드

## 시작하기

실행용 ZIP을 모두 풀고 맨 위의 **UnityBridge Desk 실행.exe**를 실행합니다. 실행 파일과 `app/` 폴더를 함께 보관하세요. Unity와 Bridge는 별도로 준비합니다. 고정 명령 벤치에는 AI 계정이 필요하지 않습니다.

1. 상단 **보관함 → 빠른 설정**을 엽니다.
2. 찾아 둔 프로젝트에서 **이 프로젝트 사용**을 누릅니다.
3. 사용할 Bridge 조합을 고르고 **이 조합 등록·선택**을 누릅니다. 비교할 버전이 여러 개라면 각각 등록합니다.
4. 작업실로 돌아와 **설치·관리 / AI 작업 / 벤치마크**를 선택합니다.

보관함의 선택은 새 작업에 반영됩니다. 이미 실행 중인 작업의 대상은 바뀌지 않습니다.

## 자동으로 찾는 위치

- Unity Hub의 최근 프로젝트와 설치 위치 기록
- Unity 기본 설치 폴더, 시스템 PATH
- 앱 주변, 다운로드 폴더와 기본 Unity 프로젝트 폴더
- 보관함에 등록한 경로와 이전에 지정한 위치
- Codex 데스크톱의 로컬 설치 폴더, 사용자 설치 위치, npm의 Windows 실행 파일
- 기본 Codex 홈(`%USERPROFILE%/.codex`)과 `CODEX_HOME`으로 지정한 홈

목록에 없으면 **다른 위치의 폴더 추가**에서 프로젝트 또는 압축을 푼 Bridge 폴더를 한 번 지정하세요. 다음 검색에도 기억합니다. 검색은 로컬 읽기이며, 디스크 전체를 훑지 않습니다. 검색 깊이·폴더 수에 제한이 있고 Unity의 `Library`·`Assets` 내부는 검색하지 않습니다. 위치 기록이 없거나 읽을 수 없으면 직접 지정할 수 있습니다.

같은 폴더에 CLI와 Connector가 하나씩 있으면 조합으로 제안합니다. 같은 폴더라는 이유만으로 같은 버전임을 보증하지는 않습니다. 등록 시 표시된 경로를 확인하세요. 실제 파일·해시는 등록하면서 검사합니다.

작업 준비를 열면 **Unity Editor / AI 프로그램 · Codex / Codex 로그인 정보** 카드에서 자동 확인 결과를 볼 수 있습니다. 찾은 항목은 그대로 사용하면 됩니다. 긴 경로는 **위치 확인 · 직접 지정**에 접어 두었습니다.

1. Unity는 먼저 보관함에서 프로젝트를 선택하세요. `ProjectVersion.txt`와 일치하는 Editor를 찾아 연결합니다. 설치되어 있지 않으면 카드에 표시된 버전을 Unity Hub에서 설치하고 **다시 찾기**를 누릅니다.
2. Codex 프로그램을 찾았다면 실행 파일을 다시 지정할 필요가 없습니다. 다른 위치에 설치했다면 **위치 확인 · 직접 지정 → 실행 파일 찾기**에서 `codex.exe`를 한 번 선택합니다.
3. 후보가 여러 개이고 이전 선택도 없으면 목록을 펼쳐 보여줍니다. 사용할 위치를 한 번 선택하세요. 이미 지정한 유효한 경로는 **다시 찾기**를 눌러도 유지합니다. Unity 버전이 다르면 카드가 알려줍니다.

다른 도구에서 지정한 실행 파일과 로그인 홈 위치도 재사용합니다. 인증 파일은 존재 여부만 확인하며 로그인 유효성은 AI 실행 시 확인합니다. 모델과 실행 허용 여부는 직접 선택합니다.

### 로그인 파일을 찾지 못한다면

**Codex 로그인 정보 → 설정 방법**을 여세요. 현재 Desk의 AI 실행기는 `auth.json`이 들어 있는 폴더를 사용합니다. 프로그램 위치가 확인되었다고 로그인 준비까지 끝난 것은 아닙니다. **고정 명령 벤치만 사용한다면 AI 설정을 할 필요가 없습니다.**

Codex는 로그인 정보를 파일 또는 운영체제의 자격 증명 저장소에 보관할 수 있습니다. 파일 방식은 `cli_auth_credentials_store = "file"`이며, `CODEX_HOME`(기본 `%USERPROFILE%/.codex`)에 `auth.json`을 저장합니다. [OpenAI 공식 인증 안내](https://learn.chatgpt.com/docs/auth)

이미 파일 방식으로 로그인했다면 **다시 찾기**, 별도 홈을 사용한다면 **위치 확인 · 직접 지정 → 폴더 선택**으로 연결합니다. 파일이 없는 경우 공식 안내에 따라 파일 저장 방식으로 로그인한 뒤 다시 찾으세요. Desk가 기존 로그인 설정을 자동으로 변경하지는 않습니다. 인증 파일 내용은 입력하거나 공유하지 마세요.

## 개별 등록과 비교 조합

빠른 설정 옆의 **프로젝트 / 로컬 파일 / 릴리스 조합** 탭에서 세부 구성을 지정할 수 있습니다.

- 프로젝트: `Assets`·`Packages`·`ProjectSettings`가 있는 폴더를 선택합니다.
- CLI: Windows `.exe` 파일을 선택합니다.
- Connector: `package.json`이 있는 폴더를 선택합니다.
- 릴리스 조합: 등록한 파일을 묶고 비교 축을 지정합니다. CLI만 비교할 때는 모든 조합에 **동일 해시의 Connector**를 지정합니다.

표시 이름과 실제 파일 버전은 별개입니다. 같은 내용의 파일은 해시로 중복 등록을 막습니다. **다시 확인**은 현재 내용을 검사하고, **경로 다시 지정**은 이동한 파일이 등록 때와 같은 내용인지 확인합니다. 목록에서 제거해도 원본 폴더나 파일은 삭제하지 않습니다.

## 세 도구

| 도구 | 준비 | 시작 후 수행하는 일 |
|---|---|---|
| 설치·관리 | 프로젝트, Editor, CLI·Connector 조합 | Bridge 의존성 적용, 컴파일·실제 응답 확인 |
| AI 작업 | 자연어 지시, 프로젝트·조합, AI 실행 파일·모델·인증 홈·허용 선택 | 별도 채팅창 없이 지시 전달, 변경·Bridge 확인 기록 |
| 벤치마크 | 프로젝트, 비교 버전, 고정 명령·AI 모드와 실험 | 시행마다 새 복제본과 Editor에서 실행, 결과 비교 |

설치·관리의 **설치 구성 열기**, AI 작업의 **AI 실행 구성**은 초안 화면 하단에 있습니다. 벤치마크는 바로 **1 준비 / 2 진행 / 3 결과**가 열립니다.

화면 하단 **구성 확인**으로 실행 계획을 검토합니다. 검토를 통과하면 같은 버튼이 **설치 시작 / AI 작업 시작 / N개 시행 시작**으로 바뀝니다. 이 버튼을 눌러야 실제 작업이 시작됩니다. 입력을 바꾸면 다시 검토합니다.

첫 설치는 해당 프로젝트의 Editor를 닫고 진행합니다. 설치는 Bridge 의존성을 변경하고 manifest·lock을 백업합니다. AI 작업은 선택한 프로젝트의 파일을 변경합니다. 벤치는 원본을 복제해 사용합니다.

## 진행과 결과

진행 화면에서 현재 단계와 완료 수를 확인합니다. Unity 준비와 컴파일에는 시간이 걸릴 수 있으며, 진행 막대는 남은 시간 예측이 아니라 완료한 시행 수입니다. 탭 전환과 최소화는 실행을 중단하지 않습니다. **실행 중단**을 누르면 정리가 끝날 때까지 기다립니다.

벤치는 완료 후 이번 실행의 **3 결과**를 자동으로 엽니다. 성공·실패·중단 수를 먼저 확인한 뒤 같은 조건의 시간과 독립 시행 수를 비교하세요. **지난 결과 보기** 또는 결과 목록에서 이전 실행을 선택합니다. **원시 기록·오류 상세**에서 실패 원인을, **선택 결과 내보내기**에서 JSON·CSV 저장 위치를 확인합니다. [측정값 해석](BENCHMARKS.md)에 단위와 표본 규칙을 설명합니다.

## 작업실과 저장

상단 **도구 ⌄**에 포인터를 잠시 올리면 선택 패널이 내려옵니다. 클릭·키보드로도 열 수 있습니다. 작업 화면은 고정되고 도구를 전환해도 입력과 결과가 유지됩니다. **테마**에서 Lilac·Rose·Mint와 시계 표시를 선택합니다. 오른쪽에는 시계·작업 요약·최근 결과·구름 고양이가 있습니다.

| 단축키 | 동작 |
|---|---|
| Alt+1~3 | 도구 선택 |
| Ctrl+K | 도구 찾기 |
| Ctrl+Tab / Ctrl+Shift+Tab | 다음 / 이전 도구 |
| Esc | 열린 선택 패널 닫기 |

입력을 잠시 멈추면 자동 저장합니다. 정상 종료 시 마지막 저장을 기다립니다. 기본 데이터 위치는 `%LOCALAPPDATA%/UnityBridgeDesk`이며, `settings/local-setup.json`에는 기억한 위치만 저장합니다. AI 호출 허용은 저장하지 않습니다. 앱 ZIP에는 개인 설정·실행 기록·인증 파일을 넣지 않습니다.

## 문제가 생겼을 때

- 경로를 찾지 못하면 **빠른 설정 → 다른 위치의 폴더 추가** 또는 입력란의 **찾기**를 사용합니다.
- 실행되지 않으면 준비 화면의 누락 안내와 검토 오류를 확인합니다. 숫자 오류는 해당 입력란으로 이동합니다.
- 준비 실패는 결과의 원시 기록과 시행 폴더의 `editor.log`에서 확인합니다.
- 앱이 비정상 종료되었다면 **미완료 기록 확인**으로 중단 기록을 정리하고 새 실행을 시작합니다.
- 같은 저장 위치를 사용하는 다른 Desk가 있으면 보관함이 읽기 전용일 수 있습니다.
- 기록을 공유할 때는 개인 프로젝트 경로나 지시가 남아 있는지 확인합니다. 인증 파일을 결과와 함께 보내지 않습니다.
