# 로컬 속도 벤치 사용 가이드

## 처음 실행

1. ZIP 전체의 압축을 풀고 `UnityBridge Desk 실행.exe`를 실행합니다.
2. 준비 탭의 **Unity 환경**에서 자동으로 찾은 Editor를 확인합니다. 여러 개면 목록에서 선택할 수 있습니다. 기본 설치 경로와 Unity Hub 기록, 이전에 선택한 위치를 탐색합니다.
3. **비교 대상**에서 UnityBridge 두 버전 이상을 선택하고 **비교 기준**을 지정합니다. **공식 Unity CLI + Pipeline 함께 비교**를 켜면 UnityBridge 한 버전만 선택해도 시작할 수 있습니다. 전체 대상 수는 2~8개입니다. 첫 실행에는 릴리스 목록을 조회하며, RC는 직접 선택합니다. 이후 목록은 새로 확인 버튼으로 갱신합니다.
4. **측정할 작업**과 하단의 예정 시행 수를 확인한 뒤 **벤치 시작**을 누릅니다. **파일 미리 준비**는 사전 다운로드용이며 필수 단계가 아닙니다.

Unity는 설치·활성화돼 있어야 합니다. 앱은 Unity 설치나 라이선스 로그인을 대신하지 않습니다. 가상머신, 별도 사용자 계정, 관리자 실행은 요구하지 않습니다. 회사 PC 등에서 Unity 실행이 제한되면 해당 정책에 따라 준비해야 합니다.

기존 개인 Unity 프로젝트를 지정하지 않습니다. 모든 실험은 앱이 만든 새 최소 프로젝트에서 수행합니다. CLI와 Connector는 버전별로 자동 보관하고 해시를 검사합니다. RC의 런타임 전체도 자동 준비합니다. [RC-INSTALL.md](RC-INSTALL.md)

공식 Unity 비교는 설치·활성화된 **Unity 6**가 필요합니다. **공식 도구 버전 지정 (선택)**을 비우면 시작 시 CLI·Pipeline 버전을 자동 선택하고 파일도 준비합니다. 정확한 버전을 입력해 고정할 수도 있습니다. 선택은 저장되며 결과의 **설정 재사용**으로 실제 사용 버전을 복원할 수 있습니다. 별도 스크립트나 CLI 경로 입력 없이 같은 시작·중단·결과 버튼을 사용합니다. [공식 Unity 비교 상세](OFFICIAL-UNITY-COMPARISON.md)

공식 도구 파일은 Desk 전용 임시 보관함에 내려받고 벤치 종료·오류·취소 시 삭제합니다. **파일 미리 준비** 후 실행하지 않고 앱을 닫아도 삭제합니다. 다음 벤치는 다시 다운로드하므로 인터넷 연결이 필요하며, 다운로드 시간은 속도 통계에서 제외합니다. 결과의 **시험 요약**과 TXT에서 **공식 CLI·Pipeline 임시 보관함 삭제 확인**을 확인할 수 있습니다.

## 실험 조건

- F01: 첫 명령 완료 시간 / 반복 명령 평균 시간. 두 조건은 서로 다른 새 프로젝트에서 측정합니다.
- F02: 오브젝트 1,000개 이동을 1·10·100개 명령으로 분할.
- F03: 1 KiB·64 KiB·1 MiB 고정 본문 반환.
- F04: 같은 C# 파일을 exec로 처음 실행하거나 준비 호출 이후 실행.
- S01: 명령별 고부하·고밀도 요청. 기본 5개 시나리오, 요청 32개·동시 4개. 부하 설정에서 수치와 다른 명령을 지정할 수 있다. [입력 형식·근거·제한](STABILITY.md)
- 새 프로젝트 반복 N: 매번 Unity·프로젝트를 새로 준비하는 반복 수.
- 제외할 사전 실행 W: 측정 전에 실행하는 호출 수. F01·F04 첫 명령과 S01에는 적용하지 않습니다.
- 실험당 측정 명령 M: 한 시행 안의 반복 호출 수. 별도 시행으로 세지 않습니다.

기본 F01, N=2, W=1, M=3에서 두 버전을 선택하면 8개 시행입니다. Unity 준비와 컴파일을 매 시행 반복하므로 시간이 걸립니다. 작은 예비 설정으로 통계적 승자를 판정하지 않습니다.

**벤치 설정 초기화**는 실험·횟수·시간 제한·시드를 기본값으로 돌립니다. Unity·버전 선택과 결과는 보존하며 직전 초기화는 되돌릴 수 있습니다.

## 진행과 중단

`새 실험 폴더 준비 → Unity 실행·컴파일 → 고정 명령 측정 → 결과 저장·프로세스 종료 → 폴더 정리`

진행 탭에서 현재 버전, 조건, 시행 순서와 단계를 봅니다. 좌측에는 계획한 시행을 번호순으로 표시합니다. 번호·버전·실험 검색과 전체 / 진행 중 / 실패·정리 실패 필터를 사용할 수 있습니다. 다른 시행을 살펴보는 동안 새 진행 이벤트가 와도 선택을 바꾸지 않으며 **현재 시행으로**를 누르면 돌아갑니다. 시행 선택은 조회이며 다시 실행하지 않습니다. Unity 준비 시간은 CLI 속도에 포함하지 않습니다. 측정 중에는 다른 무거운 작업을 줄이면 비교 변동을 줄이는 데 도움이 됩니다.

진행 막대는 **종료한 시행 수 / 계획한 시행 수**입니다. 실패한 시행도 종료 수에는 포함되므로 완료 비율이 성공률을 뜻하지 않습니다. 상단 경과 시간은 파일 준비부터 걸린 전체 시간이며 CLI 측정값과 다릅니다. 단계 표시는 관측한 준비·Unity 기동·측정·정리 이벤트를 사용하고 예상 완료 시간을 임의로 계산하지 않습니다. **상세 실행 로그**를 펼치면 전체 메시지를 읽을 수 있습니다.

시작을 누르면 진행 탭으로 이동합니다. 이후에는 사용자가 선택한 탭을 유지하며, 종료 뒤 **결과 확인**을 누르거나 **결과**로 이동합니다. `Alt+1·2·3`으로 탭을 선택할 수도 있습니다. 상단은 진행 상태·경과 시간·시계를 표시하고 최근 알림은 **설정**에서 확인합니다.

중단 버튼을 누르거나 창을 닫으면 시험 프로세스 묶음을 종료하고 정리를 기다립니다. 원래 열려 있던 개인 Unity 프로세스를 찾아서 종료하지 않습니다. 폴더 삭제·프로세스 종료가 확인되지 않으면 다음 시행을 멈춥니다.

앱 프로세스가 강제 종료돼도 운영체제의 Job Object가 그 묶음의 프로세스를 종료하도록 구성했습니다. 남은 작업 폴더는 다음 벤치 시작 전에 소유권과 실행 상태를 확인해 정리합니다. 파일 잠금·전원 차단·공유 서비스 등 모든 상황의 무잔여를 보장하지는 않습니다. 소유 표식이 없거나 관련 프로세스가 살아 있으면 임의 삭제하지 않습니다.

## 결과 확인

1. 선택 조건의 평균 시간 차이와 통계 포함·제외 횟수를 확인합니다. 전체 **계획·기록·성공·실패·중단·정리 실패·미수행**은 **시험 요약**에 있습니다. **내보내기 → 비교 요약 TXT 열기**로 시간 차이와 상세 수치를 읽고, **비교 요약 복사**로 설명만 복사합니다.
2. 같은 조건과 버전의 평균·중앙값을 확인합니다. 단위는 ms입니다.
   **조건별 시간**에서 조건과 지표(평균 완료 시간 / 유효 완료율)를 바꿀 수 있습니다. 시행 상세의 **안정성 요약**에서 오류 종류·시간 변동·성공 호출 P95·부하 처리량을 확인합니다.
3. 버전 비교는 같은 블록에서 두 버전 모두 성공하고 정리가 확인된 경우만 사용합니다.
4. 좌측에서 실험·조건과 개별 시행 번호를 고르면 중앙에 상세가 표시됩니다. 번호를 직접 검색하거나 버전·상태 필터를 펼쳐 목록을 좁힙니다. 선택한 시행의 오류와 **임시 폴더 정리** 상태를 확인하고 **이 시행의 로그 열기**로 로그를 봅니다. **시행 표로 보기**는 필요한 때 펼칩니다. 필터 초기화는 시행 목록에만 적용됩니다.
5. **내보내기 → 분석 Excel 열기 / 보고서 폴더 열기**로 요약 TXT·분석 Excel·실패 내역·SVG 그래프를 확인합니다. 과거 기록도 재실험 없이 생성합니다.
6. JSON·CSV·전체 로그는 **내보내기 → 원본·로그 폴더 열기**에서 엽니다. 이전 방식의 기록과 테마 변경은 오른쪽 위 **설정**에 있습니다. [결과 파일의 구조와 읽는 기준](RESULTS.md)을 참고하세요.

**설정 → 화면**에서 연보라·로즈·민트 풍경과 일반 화면, 움직임 사용을 선택합니다. **설정 → 캐릭터**에서는 고양이 아라와 여우 아샤를 각각 켜거나 둘 다 켤 수 있습니다. 탐색·활동량·처음 자리로 돌아가기도 개별 제공하며 다음 실행에 복원합니다. 아라는 높은 곳을 선호하고, 아샤는 넓고 낮은 발판을 빠르게 탐색하며 냄새 맡듯 살핍니다. 끌어 놓으면 실제 발판까지 떨어집니다. 벤치와 설정 팝업 중에는 둘 다 숨고, 앱 비활성화·최소화 시 정지합니다. [캐릭터 사용법](CHARACTERS.md)

원시 결과에는 실제 경로·컴퓨터 이름이 포함됩니다. 공개 전에 확인하세요. 실패를 0ms로 합산하지 않습니다. 폴더에 들어 있는 dump는 이름과 크기를 기록한 뒤 작업 폴더와 함께 정리하며, 원본 대용량 dump를 결과에 복사하지 않습니다. 전역 Windows 오류 보고 저장소는 건드리지 않습니다.

## 저장 위치

기본 루트: `%LOCALAPPDATA%/UnityBridgeDesk/speed`

| 위치 | 내용 |
|---|---|
| `local-settings.json` | Unity 선택, 실험 조건, 테마, 버전·비교 기준과 공식 도구 선택 |
| `releases` | 정식·RC CLI와 Connector 보관함 |
| `local-work/<시행 ID>` | 임시 프로젝트·CLI 복사본·캐시·임시 파일. 완료 후 삭제 |
| `official-work/<임시 ID>` | 이번 벤치의 공식 CLI·Pipeline·의존 패키지 다운로드 원본. 벤치 종료 또는 앱 종료 시 삭제 |
| `local-runs/<실행 ID>` | 결과 JSON·CSV, 요청 명세, 로그와 상태 기록 |
| `reports/<시작 시각·실행 ID>` | 읽기용 요약 TXT, 분석 Excel, 실패 내역. 원본에서 재생성 가능 |
| `runs`, `vms`, `settings.json` | 이전 VM 방식 자료. 보존하며 새 결과와 혼합하지 않음 |

현재 방식은 Windows 사용자 설정·시스템 캐시·공용 서비스를 공유합니다. TEMP/TMP 변경만으로 사용자 프로필이 격리됐다고 표시하지 않습니다. 상세 범위는 [LOCAL-BENCH.md](LOCAL-BENCH.md)를 참고하세요.

횟수와 시간 제한은 입력칸에 숫자를 직접 입력한다. 범위를 벗어나면 해당 입력 아래에 안내한다. 선택한 시험에 사용하지 않는 입력은 비활성화한다. 하단 시작 버튼 옆에 부족한 준비 조건을 표시하며 준비가 끝나야 버튼이 활성화된다. Unity 재탐색·릴리스 조회 중에는 해당 영역에 진행 상태를 표시한다.

좌측은 준비 목차 / 진행 시행 / 결과 실험·조건·시행 탐색을 담당한다. 좁은 창에서는 목록을 접어 중앙 공간을 확보하며 **목록** 또는 `Alt+0`으로 펼친다. 작은 시계와 진행 상태는 상단에 표시한다.

결과 탭은 좌측에서 실험·조건을 먼저 선택하고 중앙의 **조건별 시간 / 기준 버전 대비 / 시행 상세**를 전환한다. 세로 막대를 누르면 해당 버전의 시행으로 이동한다. 좌측 **실행 기록**의 검색창으로 이전 실행을 찾은 뒤 **선택한 결과 열기**로 열고, **설정 재사용**으로 조건을 가져온 뒤 별도로 시작한다. **내보내기 → 현재 그래프 SVG 저장**으로 선택 조건의 이미지를 저장할 수 있다.

## 빠른 이동

Ctrl+N은 준비 중인 초안, Ctrl+H는 실행 기록이다. 실행 기록에서 Escape 또는 작업으로 돌아가기를 누르면 이전 탭으로 돌아간다. 설정 팝업은 닫기 버튼·Escape·바깥 영역 클릭으로 닫으며 작업과 선택을 유지한다. 팝업이 열린 동안 작업 전환 단축키는 동작하지 않는다. Alt+1·2·3은 준비·진행·결과, Alt+0은 사이드바 접기·펼치기다. 시작이 비활성화돼 있으면 하단 안내와 **확인할 설정으로**를 이용한다. 기록 조회는 새 벤치를 실행하지 않으며 진행 중인 벤치도 중단하지 않는다.
