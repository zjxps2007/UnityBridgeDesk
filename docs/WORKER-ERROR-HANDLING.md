# Worker 시작 오류 처리

2026-09-21 · v0.5.0 미배포 수정

## 확인한 원인과 범위

05:32 개발 검증 중 `--calibrate`에 상대 경로를 전달했을 때 실행 요청의 작업 폴더가 절대 경로 검사를 통과하지 못했다. 당시 `ArgumentException`이 처리되지 않아 Worker가 비정상 종료했다. 작업 폴더와 Worker 경로를 절대 경로로 정규화하고 진단 예외 처리를 보완했으며, 동일한 상대 경로 사용 방식으로 합성 진단 60회를 완료했다.

이후 사용자가 작업 중 떠 있던 Windows 오류 창을 공유했다. 화면의 `0xe0434352`와 주소만으로 개별 원인을 확정하지 않는다. 당시 오류일 가능성이 있으나 새 발생 기록은 확인되지 않았다.

## 추가 처리

- Worker의 모든 명령 분기와 표준 입력 처리를 최상위 예외 경계로 감싼다. 처리되지 않은 관리 예외는 표준 오류에 예외 종류·메시지·스택을 남기고 종료 코드 1을 반환한다. 취소는 130이다.
- 정상 출력과 부모 통신 프레임에 오류 텍스트를 섞지 않는다. 잘못된 요청이 성공 결과 파일을 만들지 않는다.
- 부모 WorkerRunner가 이전에 읽기만 하고 버리던 시작 진단을 ProcessResult.Error에 보존한다. 프레임 없이 종료되면 실패 상태를 유지한다.
- 로컬 시행은 기존 worker.json 증거와 실패 상세를 통해 원인을 확인한다. 직접 Worker를 실행하는 개발 진단은 표준 오류를 확인한다.
- Windows 오류 보고 설정·덤프 설정은 변경하지 않는다. 이 경계는 복구 가능한 관리 예외에 대한 처리이며 런타임 자체의 치명적 손상을 복구한다고 주장하지 않는다.

## 검증

실제 Worker 프로세스에 요청 파일 누락·JSON 손상·기록 폴더 누락·진단 출력 경로 충돌·손상된 입력 프레임·잘못된 문자 인코딩을 전달한다. 정상적인 실패 종료, 원인 보존, 성공 결과 미생성을 확인한다. 기존 프로세스 취소·자식 정리·출력 크기 제한 시험도 함께 검사한다. Unity나 실제 벤치는 시작하지 않는다.

검증 결과: 솔루션 Release 빌드 경고·오류 0건, Infrastructure 검사 215개 통과(신규 6개 포함), 실패·건너뜀·검사 프로세스 종료 오류 0건이다. 이번 수정은 UI를 변경하지 않았다.
