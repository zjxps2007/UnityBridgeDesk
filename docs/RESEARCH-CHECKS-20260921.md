# 연구 검증 기능의 구현 검사

2026-09-21 · v0.5.0 기반 미배포 보완이다. 실제 Unity A/A 실험이나 외부 재현을 통과했다는 기록이 아니다.

## 자동 검사

Core 38개, Infrastructure 201개, Desktop 76개로 총 315개가 통과했다. 빌드 경고·오류는 없었고 테스트 호스트 종료 예외도 검출되지 않았다. 기존 v0.5.0 기록의 321개에는 별도 앱 Companion 13개가 포함되어 있었다. 이 저장소에서는 Desk만 검사한다. 이번에는 연구 검증 검사 6개와 과거 보고서 형식 10 보존 사례 1개를 추가했다.

새 검사는 동일 원본 A/A의 파일 식별 정보, 서로 다른 시행 ID, 실행 순서 균형, RC 버전 보고 예외, 사전 계획 변경 탐지, 미완료·추세·허용 경계 판정, 내보내기 취소와 원본 보존을 다룬다. WPF 검사는 연구 설정의 읽기·쓰기, 잘못된 선택 차단, 초기화·되돌리기, 기존 공식 CLI 비교 버튼 동작을 포함한다. 960×600 및 1440×850, 100%·150% 배율의 연구 설정을 렌더링해 검토한다.

연구 ZIP 두 개를 앱에서 만든 뒤 Python으로 독립 검산했다. 성공·실패·미수행이 섞인 자료와 30쌍 합성 자료에서 표본 수, 평균, Student 구간, Fieller 시간비 구간이 앱과 수치 허용 오차 안에서 일치했다. Student 분위수 참조값 5개와 설정 변경 후 파일 해시만 다시 쓴 자료의 계획 불일치 탐지도 확인했다. 이 검사는 계산 구현의 일치를 확인하며 실제 측정값의 진실성이나 통계 가정을 증명하지 않는다.

## 첫 계측 진단에서 관찰한 값

합성 진단 ID는 `calibration-83a742b1b7d640c0ae3224f2b8cb4c78`이다. 0·25·100ms 대기를 블록 내에서 무작위 순서로 실행했으며, 사전에 정한 20블록·60개 프로세스를 모두 완료했다. Unity와 Bridge는 실행하지 않았다. 이 진단 동안 다른 빌드·테스트를 함께 실행하지 않았다. Windows의 외부 작업까지 정지하거나 통제한 것은 아니다.

잔차는 `(지연 조건 외부 시간 − 0ms 외부 시간) − (지연 조건 실제 내부 시간 − 0ms 실제 내부 시간)`이다.

| 지연 요청 | 유효 쌍 | 잔차 평균 | 쌍 단위 95% t 구간 |
|---|---:|---:|---:|
| 25ms | 20 | −6.31ms | [−10.96, −1.65]ms |
| 100ms | 20 | −5.55ms | [−10.22, −0.88]ms |

외부 측정에서 추가되는 시간이 두 조건 사이에서 일정하지 않았다는 관찰이다. 외부 시간에는 프로세스 시작·출력 수집·종료와 스케줄링이 포함되므로, 이 잔차를 타이머 자체의 오차로 단정할 수 없다. 0ms 분기의 실행 경로와 지연 분기의 실행 경로도 완전히 같지 않다. 동일 릴리스를 실제 Unity에서 실행하는 A/A가 추가로 필요하다. 위 평균을 실제 벤치 결과에서 일괄 차감하지 않는다.

## 실행 잠금 보완 후 확인

일반 벤치와 계측 진단이 동시에 시작되지 않도록 같은 파일 잠금을 적용한 뒤 60회 진단을 다시 완료했다. 진단 ID는 `calibration-fd399884053a48ec8b4633534704a02a`이다. 정상 종료 여부를 확인하기 위한 재실행이며, 앞선 값을 대체하거나 두 자료를 합쳐 유리한 결론을 만들지 않는다.

| 지연 요청 | 유효 쌍 | 잔차 평균 | 쌍 단위 95% t 구간 |
|---|---:|---:|---:|
| 25ms | 20 | −3.11ms | [−6.66, +0.44]ms |
| 100ms | 20 | −3.30ms | [−6.33, −0.28]ms |

두 번 모두 실행은 완료했으나 잔차가 일정한 보정 상수라는 근거는 없다. 이 자료로 정확성 통과 판정을 내리지 않는다.

## 해석 범위와 후속 확인

- 사전 계획 일치는 로컬 기록의 일치다. 외부 사전등록이나 전자서명을 대신하지 않는다.
- Worker EXE·Unity EXE의 해시만으로 전체 설치와 모든 의존 어셈블리의 동일성을 보장하지 않는다. 재현 자료에는 실행용 묶음의 `distribution.json`과 같은 소스 리비전·전체 배포 파일을 함께 고정해야 한다.
- 현재 진단의 t 구간은 진단용이다. 분포·의존성·실패 패턴에서 구간의 장기 포함률을 검증한 결과가 아니다.
- 성공 조건부 시간과 실패·제외 수를 함께 읽는다. 실패한 실행을 빠른 성공으로 집계하거나 표본을 임의로 버리지 않는다.
- 다음 실험은 실제 Unity A/A, 별도 세션 반복, 작업별 어댑터 동등성 확인, 제삼자 재실행 순서로 진행한다. 각 단계의 결과에 따라 주장 가능한 범위를 넓힌다.

사용법과 판정 규칙은 [연구용 검증 안내](RESEARCH-VALIDATION.md)를 참고한다. 이번 기능 추가를 계측 정확성 인증이나 논문 채택 보장으로 표시하지 않는다.
