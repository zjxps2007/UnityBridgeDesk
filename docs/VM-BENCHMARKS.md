# VM 속도 벤치 측정 방식

구현 스키마는 `vm-cli-completion-v1-pilot`입니다. 실제 VM·Unity 통합 실측은 아직 수행하지 않았습니다. 설계의 논거와 정식 시험 목표는 [방법론](BENCHMARK-METHODOLOGY.md), 현재 구현·검증 범위는 [VM-PILOT.md](VM-PILOT.md)를 참고하세요.

## 비교 질문

같은 호스트·VM 기준 이미지·자원·Unity·도구·입력에서 **릴리스의 CLI + Connector 조합**만 바꾸었을 때, 올바른 명령 결과를 받는 시간이 달라지는지 비교합니다. CLI와 Connector 중 어느 하나가 원인인지 분리해서 주장하지 않습니다.

## 실험

| 실험 | 준비 | 측정 | 검증 |
|---|---|---|---|
| F01 첫 호출 | 새 VM 시행에서 Unity ready 확인, CLI 준비 호출 없음 | `echo` 1회 | 고정값 42, 요청 식별값, Unity PID와 프로젝트 |
| F01 반복 호출 | 별도 VM 시행, `echo` W회 | `echo` M회 | 각 응답의 값과 대상 |
| F02 명령 분할 | 오브젝트 1,000개 생성, `echo` W회 | 같은 이동을 1·10·100개 순차 명령으로 분할 | 이동 수, 최종 오브젝트 ID·개수·위치 |
| F03 응답 크기 | 해당 크기의 응답 W회 | 1 KiB·64 KiB·1 MiB 고정 ASCII 본문 각각 M회 | 길이와 본문 전체, 요청과 대상 |

모든 실험은 두 버전에 같은 `desk_probe` 소스를 넣어 사용합니다. 준비용 최소 프로젝트를 게스트 안에 새로 생성합니다. 실험 크기는 이 프로그램의 선택이며 보편적인 표준 부하가 아닙니다. 내장 도구 전체나 게임 FPS를 대표하지 않습니다.

## 실행과 고립 범위

릴리스 원본은 호스트 보관함에 해시로 고정합니다. 자체 런타임 포함 Worker·CLI·Connector·요청을 준비한 VM에 전달합니다. Unity·CLI·계측기는 게스트에서 실행됩니다.

RC는 EXE 옆 런타임 폴더까지 전달하고 전체 해시를 검사합니다. ZIP 압축 해제는 준비 단계에 한 번 수행합니다. 구버전 단일 EXE가 명령 실행 중 자체 런타임을 푸는 비용은 그 버전의 실행 시간에 포함됩니다. 따라서 공식 배포 형식 차이도 비교 대상이며, 속도 차이를 내부 명령 알고리즘 하나의 효과로 단정하지 않습니다. [RC 준비 방식](RC-INSTALL.md)을 참고하세요.

준비 단계에는 NAT 네트워크를 허용합니다. Unity ready를 파일로 확인하면 호스트가 가상 네트워크 케이블을 끊고 차단 상태를 확인한 뒤 측정 허가를 보냅니다. 게스트는 허가 후 고정 500 ms를 기다립니다. 이 대기와 파일 전송은 측정 밖이며 ready부터 첫 측정까지의 간격도 기록합니다.

매 독립 시행 전후 같은 전원 꺼진 스냅샷으로 복원합니다. TEMP·사용자 프로필·레지스트리에 이전 시행 표식이 남아 있으면 거부합니다. 공유 폴더, 외부 기준 디스크, 복원되지 않는 디스크 종류는 허용하지 않습니다. 앱 소유 표식과 VM ID를 확인한 전용 복제 VM만 제어합니다.

VM 복원은 게스트 상태를 분리합니다. 물리 CPU·발열·호스트 부하·물리 캐시·다른 가상화 제품의 부하는 여전히 결과에 영향을 줄 수 있습니다.

## 시간의 경계

주 지표는 **게스트의 CLI 프로세스 시작 직전 → 프로세스 종료와 표준 출력·오류 수집 완료**입니다. 단조 시계 `Stopwatch`를 사용합니다.

포함: CLI 프로세스 기동, 요청 처리·응답 직렬화·수집, CLI 내부 작업.  
제외: VM 복원·부팅, 파일 전송, Unity 기동·컴파일, 계측기 자신의 해시 검사, JSON·값 검증, 정리.

F01·F03은 각 CLI 시간을 보존하고 한 시행의 평균을 대표값으로 사용합니다. F02는 첫 명령 시작부터 마지막 명령 수집 완료까지 연속 구간을 사용하므로 명령 사이 제어기의 간격도 포함합니다. 모든 응답의 정확성 검증은 이 구간 뒤에 수행합니다.

이 값은 Unity 내부 함수만의 처리 시간이 아닙니다. 기존 호스트 Worker·해시 검사가 포함된 `draft-v1` 시간과 직접 합산하지 않습니다.

## 반복·실패·통계

같은 실험·조건의 각 반복을 블록으로 묶고, 블록 안에 선택한 모든 릴리스를 한 번씩 배치합니다. 버전 시작 순서를 회전 배치한 뒤 시드로 블록을 섞습니다. 각 항목은 새로 복원한 VM 시행입니다.

- N은 독립 VM 반복 수, W는 준비 호출 수, M은 한 시행 안의 측정 수입니다.
- 성공·실패·중단·미수행을 모두 남깁니다. 누락 시간을 0으로 채우지 않습니다.
- 요청 식별값·PID·프로젝트·결과 값·표본 수·해시·Unity 버전·복원 확인을 통과한 시행만 성공 통계에 포함합니다.
- 평균·중앙값·최솟값·최댓값과 성공/계획 수를 표시합니다.
- 두 버전 비교는 둘 다 성공한 동일 블록만 사용합니다. 시간 감소율은 `100 × (1 − 비교 버전 평균 / 기준 버전 평균)`이며 실패율과 함께 읽어야 합니다.
- 현재는 예비 기술 통계만 제공합니다. 신뢰구간, p95, 자동 표본 수 결정, 종합 점수와 정식 우열 판정은 구현하지 않았습니다.

기본 N=2·W=1·M=3은 실행 경로 확인용입니다. 실제 예비 시험으로 준비 호출의 안정성과 시행 간 변동을 확인하고 본시험의 W·N·M을 미리 정해야 합니다.
