# RC 설치 방식 반영

UnityBridge **0.2.2-rc.1부터 공식 Windows 배포가 단일 EXE에서 EXE+런타임 ZIP으로 바뀌었습니다.** 이 앱의 새 준비기는 두 형식을 모두 지원합니다.

## 앱에서 사용하는 방법

1. 준비 탭에서 **릴리스 새로 확인**을 누릅니다. 예전에 저장한 목록에 RC가 비활성화되어 있으면 반드시 새로 확인하세요.
2. 비교할 정식·RC 버전을 2개 이상 선택합니다. RC는 자동 선택하지 않습니다.
3. **벤치 시작**을 누르면 파일도 자동으로 준비합니다. 사전 다운로드만 원할 때는 **선택한 파일 준비**를 누릅니다. 단일 EXE인지 런타임 ZIP인지 목록에 표시합니다.
4. 앱이 버전별 폴더에 준비합니다. 사용자가 CLI 옆에 DLL을 찾아 붙이거나 전역 설치 경로를 바꿀 필요가 없습니다.
5. 자동으로 찾은 Unity에서 선택한 버전별로 측정합니다.

원하는 태그의 공식 배포 파일을 직접 받습니다. `main/install.ps1`, 전역 `unity-bridge update`, PATH에 있는 CLI를 통해 비교 버전을 바꾸지 않습니다. RC 전용 설치 스크립트가 사용하는 배포 형식과 파일 구성을 앱의 전용 보관함에서 재현합니다.

## 배포 형식

| 릴리스 | 공식 Windows 배포 | 벤치의 준비 방식 |
|---|---|---|
| 0.2.0·0.2.1 | 단일 EXE | EXE와 해당 태그 Connector를 버전별 보관 |
| 0.2.2-rc.1·rc.2 | ZIP | `unity-bridge.exe`와 바로 옆 `_unity_bridge_runtime_<build-id>` 전체 보관 |

ZIP을 우선하고, 없으면 `unity-bridge-windows-amd64.exe`, 이전 이름인 `unity-bridge-windows-x64.exe` 순서로 찾습니다. 버전 문자열만 보고 배포 형식을 단정하지 않습니다.

RC EXE만 복사하면 실행할 수 없습니다. 앱은 런타임 폴더 이름·하위 파일을 유지해 실험 폴더에 복사합니다. 예전 버전의 런타임 위에 새 파일을 덧씌우지 않습니다.

공식 변경 내용: [RC1 릴리스](https://github.com/zjxps2007/UnityBridge/releases/tag/v0.2.2-rc.1), [RC2 설치 안내](https://github.com/zjxps2007/UnityBridge/blob/v0.2.2-rc.2/docs/INSTALL.md).

## 해시와 측정의 구분

- **배포 파일 해시**: GitHub의 게시자 SHA-256을 다운로드한 ZIP 또는 단일 EXE와 대조합니다.
- **실행 파일 해시**: ZIP 안의 EXE 자체를 별도로 고정합니다. ZIP 해시와 EXE 해시는 같은 값이 아닙니다.
- **CLI 전체 해시**: 상대 파일 이름과 각 파일의 내용으로 EXE+런타임 전체를 고정합니다. `cli-tree-v1` 방식을 사용합니다.
- **Connector 해시**: 선택 태그가 가리키는 고정 커밋의 UPM 패키지 전체를 고정합니다.

보관본 재사용과 로컬 실험 준비에서 런타임의 누락·변경을 확인합니다. 변조된 보관본은 재사용하지 않으며 다시 받을 때 새 폴더에 준비합니다. ZIP 경로 이탈, 여러 런타임 혼합, 패키지 버전 불일치도 거부합니다.

ZIP 압축 해제·파일 전달·해시 검사는 측정 밖의 준비 단계입니다. 같은 시행 안에서 CLI 명령을 호출할 때마다 RC ZIP을 다시 풀지 않습니다. **F01 첫 호출 전에 CLI help·status 등 준비 호출을 추가하지 않습니다.**

구버전 EXE가 실행 중 자체 런타임을 푸는 비용은 그 버전의 명령 실행 시간에 포함됩니다. RC는 설치 단계에서 풀린 런타임을 사용합니다. 이는 공식 배포본의 사용자 관점 완료 시간을 비교하는 조건이며, 결과 차이를 Connector 내부 알고리즘 하나의 효과로 해석하면 안 됩니다.

## RC1의 보고 버전 오류

RC1은 패키지의 선언 버전이 `0.2.2-rc.1`인데 Heartbeat가 `0.2.1`로 보고합니다. RC2는 설치된 UPM 패키지 메타데이터에서 버전을 읽도록 수정되었습니다. [공식 RC2 수정 설명](https://github.com/zjxps2007/UnityBridge/releases/tag/v0.2.2-rc.2)

앱은 RC1을 0.2.1로 다시 이름 붙이지 않습니다. 다음 두 값을 구분합니다.

- 설치된 Connector: package.json 버전과 고정 커밋·전체 내용 해시
- 실제 보고된 Connector: 해당 Unity PID·프로젝트의 Heartbeat 값

보고값 `0.2.1`을 예상하는 예외는 **태그 v0.2.2-rc.1 + 공식 커밋 74639d7b3f3adf550d58cc853b715f878153839f**에만 적용합니다. 다른 RC·다른 커밋에는 이 예외를 적용하지 않습니다. 예상 버전과 다른 보고 값이나 `unknown`은 거부합니다. 준비 화면과 시행 상세에 차이를 알리고 원시 JSON에도 예상·실제 보고 값을 남깁니다.

Connector는 동일 태그의 패키지 구조와 package.json을 유지한 채 UPM의 로컬 `file:` 의존성으로 설치합니다. Editor 스크립트만 Assets에 복사하지 않습니다. CLI를 준비했다고 Connector가 자동으로 동일 버전이 되었다고 가정하지 않습니다.

## 검증 범위

실제 공식 **0.2.0·0.2.1·RC1·RC2**의 다운로드, 게시자 해시, 패키지 버전·커밋, 런타임 전체 전달 후 해시, 오프라인 보관본 재사용을 별도 자료 폴더에서 검사합니다. 이전 단일 EXE 보관본도 읽을 수 있습니다.

자동 검사에는 ZIP 우선 선택, 런타임 손상·누락, 잘못된 ZIP 구조, 해시 불일치, 원래 보관본을 덮어쓰지 않는 복구, RC 선택 화면과 RC1 예외 제한이 포함됩니다.

현재 기본 실행은 VM을 사용하지 않습니다. 실제 로컬 Unity 연동 검증과 제한은 [LOCAL-BENCH.md](LOCAL-BENCH.md)에 기록합니다. 일반 사용법은 [USAGE.md](USAGE.md)를 참고하세요.
