# 논문 방법론을 적용한 측정·분석

2026-09-20 구현 · 2026-09-21 Desk v0.5.0 정식 배포에 통합 · 분석 규칙 `kj2013-paired-fieller-v1`

근거는 Tomas Kalibera와 Richard Jones의 **Rigorous Benchmarking in Reasonable Time**, ISMM 2013이다. [Kent 저장소](https://kar.kent.ac.uk/33611/)의 [정정된 저자 원고](https://kar.kent.ac.uk/33611/45/p63-kaliber.pdf)를 기준으로 §6, §9, §10, §11을 검토했다. [DOI: 10.1145/2464157.2464160](https://doi.org/10.1145/2464157.2464160)

논문의 핵심은 변동이 발생하는 수준을 구분하고, 예비 측정으로 반복 비용과 변동을 추정한 뒤, 효과의 크기와 불확실성을 함께 보고하는 것이다. UnityBridge 전용 표준·인증이나 이 앱의 정확성을 보증하는 문서는 아니다. 아래 실험 설정과 진단 기준은 Desk의 선택이다.

## 1. 반복의 단위

한 시행은 별도 프로젝트와 Unity 프로세스를 준비하고, 정해진 명령을 실행·검증한 다음 정리하는 과정이다. 호출마다 별도 CLI 프로세스를 시작한다. 버전별 N개 시행을 수행하고, 반복 조건은 시행 안에서 W개 사전 실행을 제외한 후 M개 호출을 측정한다.

같은 Unity 안에서 실행한 호출 M개를 서로 독립된 프로젝트 M개처럼 세지 않는다. N=10, M=20이면 원시 호출 200개와 상위 시행 10개가 있다. 평균 구간의 표본 수는 10이다. F01·F03·F04의 반복 조건은 시행별 호출 평균에 같은 가중치를 준다. F02는 1,000개 오브젝트 작업의 전체 완료 시간, 첫 명령 조건은 별도 시행의 첫 요청 한 번을 사용한다. S01은 부하 시행의 대표시간을 상위 관측값으로 사용하되 동시 호출을 독립 반복으로 취급하지 않는다.

새 프로젝트는 OS·하드웨어까지 고립한 환경이 아니다. 파일·프로세스 분리는 시행 간 잔여 상태를 줄이는 장치이며, 모든 독립성의 증거는 아니다. [실제 측정 경계](BENCHMARKS.md) · [로컬 격리 범위](LOCAL-BENCH.md)

## 2. 평균의 95% 신뢰구간 — 논문 식 (4)

유효 시행 대표시간을 `x₁ … xₙ`, 그 평균을 `x̄`, 표본분산을 `s²`라 하면 다음과 같다.

```text
s² = Σ(xᵢ − x̄)² / (n − 1)
평균의 95% 구간 = x̄ ± t(0.975, n − 1) × √(s² / n)
```

분모의 n은 상위 시행 수다. 시행별 평균을 계산한 후 사용하는 t 구간이며, 호출 수를 늘렸다는 이유로 자유도가 늘어나지 않는다. 상위 시행 간 독립성과 평균의 근사 분포를 전제로 한다. 논문 §11의 실무적 주의를 따라 유효 시행 5회 미만은 구간을 표시하지 않는다. 5회가 충분한 정확도나 정규성을 보장한다는 뜻은 아니다. 실패·정리 미확인 시행을 제외한 조건부 평균이다.

## 3. 버전 간 시간비 — Fieller의 쌍 비교 확장

같은 블록에서 기준 A와 후보 B가 모두 유효한 쌍만 사용한다. 효과는 `r = B의 평균 / A의 평균`, 시간 감소율은 `100 × (1 − r)`이다. **개별 블록의 비율을 평균하는 계산과 다르다.**

논문 §10 식 (5)는 독립된 두 집단을 다룬다. Desk는 기존 블록 쌍 설계를 유지하므로 공분산을 포함하도록 확장했다. `sA²`, `sB²`, `sAB`는 공동 유효 n쌍의 표본분산과 표본공분산이다.

```text
q = t(0.975, n − 1)² / n
u = Ā² − q·sA²
v = Ā·B̄ − q·sAB
w = B̄² − q·sB²
시간비의 95% 구간 = [(v − √(v² − u·w))/u, (v + √(v² − u·w))/u]
감소율의 구간 = [100·(1 − 시간비 상한), 100·(1 − 시간비 하한)]
```

이는 `B − rA`의 쌍 t 구간을 역으로 푼 Fieller 방식이다. 공분산을 0으로 놓으면 독립 집단 식으로 환원된다. 논문 수식을 그대로 복사했다고 표현하지 않는다. 이 구간도 분포·독립성 가정이 필요하다.

유효 쌍이 5개 미만이면 표본 부족, u≤0 등 유한한 구간을 구할 수 없으면 구간 추정 불안정으로 표시한다. 무한·분리된 신뢰집합을 임의의 유한 구간으로 바꾸지 않는다. 음수 하한을 임의로 잘라 좋은 결과처럼 보이지 않게 한다. 감소율 구간이 0%를 포함하면 방향이 불확실하다. 실패·미수행이 있으면 성공쌍에만 해당한다고 표시하며, 미완료 실행은 판단을 유보한다. 여러 조건을 동시에 비교할 때의 전체 95% 보장은 제공하지 않는다.

## 4. 사전 실행과 순서 진단 — 논문 §6

사전 실행 W는 시작 전에 고정한다. 느린 호출을 본시험 도중 임의로 제거하지 않는다. 새 기록에는 사전 실행의 CLI 완료 시간을 별도로 남기며 평균·P95의 측정 표본에는 합치지 않는다. 첫 명령 조건은 사전 실행 0회다. 과거 기록에 없는 시간은 복원하지 않는다.

시행 상세에서는 호출 순서 그래프를 표시한다. 회색은 사전 실행, 보라는 측정, 붉은색은 실패다. 측정 구간을 정렬하거나 평활화하지 않는다. F02는 사전 `echo`와 실제 이동 작업이 달라 동일 부하의 준비 완료 판정에 이 그래프를 사용하지 않는다. S01은 동시 부하이므로 순차 호출의 정상 상태 진단 대상에서 제외한다.

20개 이상인 반복 호출은 lag 1~4 자기상관을 계산하고 `|ACF| > 1.96/√M`이면 순서 영향 신호를 표시한다. 이는 Desk의 탐색용 휴리스틱이며 다중 검정 보정이나 독립성 검정의 합격 기준이 아니다. 상위 시행도 버전별 실행 순서 그래프로 확인하며, 유효 쌍 20개 이상이면 같은 방식으로 추세를 경고하고 반복 수 자동 적용을 막는다. 20개 미만은 자동 진단이 없다는 설명을 표시한다. 빈 구간은 제외·미수행이다.

신호가 없다고 정상 상태나 독립성이 증명되지는 않는다. 단조 증가·주기 변화·이상 구간을 직접 확인해야 한다. 호출 사이에 의존성이 남으면 그 묶음 평균을 관측값으로 취급하고, 상위 시행의 독립성을 별도로 점검한다. 자동 워밍업 탐지·자동 이상치 삭제·실행 중 유의성에 따른 중단은 구현하지 않았다.

## 5. 예비 실험과 반복 배분 — 논문 §9

준비의 **빠른 확인 설정**은 N=2, W=1, M=3이다. 연결·기능 확인용이며 신뢰구간을 만들지 않는다. **반복 설계용 예비 설정**은 N=20, W=5, M=20이다. 논문이 예비 상위 반복에 20~30회를 제안한다는 점을 참고한 시작값이다. 모든 장비에서 충분한 값도, W=5면 정상 상태라는 보증도 아니다. 여러 버전·조건이면 Unity 준비 횟수가 커진다. 두 버튼 모두 입력만 바꾸며 직접 시작해야 한다.

같은 호출 수 m을 갖는 정상 반복 조건에서 분산을 다음처럼 분리한다.

```text
S1² = 각 시행 안의 호출 표본분산의 평균
S2² = 시행별 호출 평균의 표본분산
T1² = S1²
T2² = S2² − S1²/m
c1 = 측정 CLI 호출의 평균 비용
c2 = 시행 전체 수명에서 측정 CLI 시간 합계를 뺀 평균 비용
다음 예비 실험의 호출 수 제안 = ceil(√((c2/c1) · (T1²/T2²)))
```

논문 식 (2)·(3)을 호출/새 프로젝트의 두 수준에 대응시켰다. c2에는 프로젝트·Unity 준비, 사전 실행, 별도 검증, 정리 등이 들어간다. 모든 비용이 호출 수와 무관한 상수는 아니므로 근사적 제안이다. T2²≤0이면 음의 실제 분산이라고 해석하지 않고 호출 수 제안을 유보한다. 위 식은 균형 반복과 시행 내부 독립성 가정을 필요로 한다. 호출이 20회 미만, 순서 신호가 있음, 표본 수 불일치, 호출 판정 누락, 실패·미완료일 때도 제안하지 않는다. 첫 명령·F02·S01에는 적용하지 않는다.

## 6. 다음 본시험 계획

시간비 구간의 **상대 반폭 5%**를 목표로 현재 예비 표본분산·공분산을 고정하고, n만 변경한 Fieller 구간이 목표에 도달하는 최소 상위 반복 수를 찾는다. 이는 논문의 정밀도·비용 설계 원칙을 Desk의 쌍 비교에 맞춘 확장이다. 5% 빠르다는 기준이나 5% 유의수준과 다르다. 최대 10,000블록까지 계산상 탐색하며 앱 실행 설정 상한은 100회다.

결과 → 기준 버전 대비 → **측정 신뢰도와 다음 실험**에서 **이 기록으로 다음 실험 준비**를 누르면 전체 조건·버전·기준·Unity 선택을 복원하고, 후보/조건별 권장값 중 최대값을 버전 수의 배수로 올림한다. 호출 수·사전 실행은 유지한다. 선택된 모든 비교가 완료·유효하고 상한 이내여야 하며 시행 순서 신호가 있으면 적용하지 않는다. 사용자 입력을 확인한 후 직접 새 실험을 시작한다. 예비 자료를 본시험 표본에 이어 붙이지 않는다.

실행 도중 표본을 추가해 원하는 구간이 나올 때 멈추는 기능이 아니다. 호출 수·환경·준비 정책을 바꾸면 현재 추정은 그대로 사용할 수 없다. 예비 분산 자체의 추정 오차와 실제 달성 정밀도의 보증은 계산하지 않는다. 상위 5개 표본만으로도 산식은 계산할 수 있으나, 예비 설정과 순서 점검을 먼저 권한다.

## 8. 적용하지 않는 범위

Desk는 공개된 바이너리·Connector를 고정한다. 컴파일러·빌드별 변화 계층은 측정하지 않는다. 앱이 코드를 다시 빌드해 공식 배포와 다른 바이너리를 비교하지 않는다. OS 캐시·온도·전원·백그라운드 부하·외부 서비스·장시간 도구 내부 상태까지 제거하지 못한다. 다중 비교 보정·검정력 분석·자동 정상 상태 판별·부트스트랩·가상머신 추가도 이번 구현에 포함하지 않는다. 과거 VM 목표 문서의 부트스트랩은 제안 기록이며 현재 분석은 위의 t/Fieller 방식이다.
