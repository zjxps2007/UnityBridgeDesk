# 반응 절제와 작업 연속성

2026-09-19 · v0.4.0 UX 후속 변경이다.

## 문제와 판단

사용자는 화면 방향은 좋지만 반응이 많아 정신없다고 피드백했다. 기존 코드에는 작업 탭의 밑줄·본문·왼쪽 목록이 동시에 움직이고, 결과 보기·시행 선택·메뉴·펼침에도 등장 효과가 있었다. 버튼 축소와 아샤의 짧은 자율 행동 간격까지 겹쳤다.

색상이나 화면 배치를 다시 바꾸기보다, 움직이는 대상과 횟수를 줄였다. 정보와 조작 위치는 고정하고 선택 밑줄과 주요 화면의 짧은 전환만 남긴다. 선택·포커스·오류·진행 상태는 계속 즉시 표시한다.

## 적용한 규칙

- 본문 이동, 버튼 축소, 목록과 본문의 중복 전환을 제거했다.
- 결과 보기·조건·시행·메뉴·펼침은 즉시 반영한다. 검색과 시행 선택 때 본문이 반복 등장하지 않는다.
- 준비·진행·결과의 선택 밑줄은 160ms, 주요 작업면은 120ms 동안 96%에서 100%로 전환한다. 같은 페이지 재선택은 반복하지 않는다.
- 아샤는 보통 활동량에서 35~55초를 쉰 뒤 자율 행동을 판단한다. 얌전함은 60~90초, 활발함은 18~28초이다. 바로 이동하지 않을 수도 있다.
- 앱으로 돌아올 때도 먼저 쉰다. 키보드 입력·버튼 조작·스크롤 중에는 걷기를 멈추고 다음 자율 판단을 미룬다.
- 아샤 위에서 약 650ms 머문 포인터에만 반응하고 최소 15초 간격을 둔다. 대기 자세의 지속적인 확대·축소를 없앴다. 클릭·끌기·걷기 프레임은 유지한다.
- 화면 설정에서 돌아가는 목적지를 기억해 실행 기록의 검색·선택을 유지한다. 다른 페이지나 기록을 선택한 뒤에는 이전 파일 읽기의 결과를 화면에 적용하지 않는다.
- 테마·일러스트·캐릭터 외형과 기존 설정값을 보존한다. 벤치의 측정 구간·명령·통계·성공 판정은 수정하지 않는다.

[frontend-design SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)의 제품 고유 정보에 따른 표현, [UI/UX Pro Max SKILL.md](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/SKILL.md)와 [quick-reference.md](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/references/quick-reference.md)의 입력 피드백·접근성·움직임 절제를 조합했다. 위 외부 문서는 같은 날 앞선 작업에서 실제로 읽은 자료이다. 이번에도 프로젝트의 디자인 작업 기준, 모션·아샤 문서와 실제 구현을 확인했다. 외부 스킬 설치나 검색 스크립트를 실행한 것은 아니다.

브라우저 CSS·모바일 스택, 모든 영역에 적용하는 등장 효과, 새 카드·배지·장식 추가는 채택하지 않았다. WPF의 기본 입력·포커스·스크롤과 Windows의 움직임 설정을 따른다. 반응을 더 끄기 위한 새 설정 단계를 추가하지 않고 기본 동작 자체를 차분하게 바꿨다.

## 검증

Desktop 자동 검사 32개가 최종 통과했다. 빌드 경고·오류는 0개이다.

실제 WPF 자동 검사는 빠른 탭 재선택과 중간 위치·정지, 본문·버튼 위치 고정, 스크롤 중 아샤 정지, 정지·숨김·복귀, 네 걷기 프레임, 화면 설정에서 실행 기록으로 돌아갈 때의 검색·선택을 확인한다. 기본 입력·스크롤·600개 합성 시행 탐색과 100·150·200% 렌더링 검사도 포함한다.

960×660 및 1440×850 창의 결과·화면 설정을 실제 WPF로 렌더링해 검토했다. 사용 중인 앱과 Unity를 종료하지 않았고, 새 Unity·유료 AI 실험은 실행하지 않았다. 화면 검토는 기존 완료 기록을 사용했다. 정적인 캡처는 동작의 시간 증거로 취급하지 않으며 모션은 실행 중 위치·타이머 검사를 통해 확인한다.
