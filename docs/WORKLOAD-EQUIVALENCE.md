# 공통 작업과 도구별 대응

2026-09-21. 입력 문자열의 일치보다 논리 작업·정답·측정 경계를 고정한다. 실제 인수는 시행 결과의 `Commands`와 도움말 기록을 함께 읽는다. 대응 기능이 없으면 다른 작업으로 대체해 같은 순위에 넣지 않는다.

| 작업 | 선행 상태·논리 작업 | 정답 확인 | 측정 경계 |
|---|---|---|---|
| F01 | 준비된 새 Editor에서 공통 echo | 42·nonce·프로젝트·PID | 명령 시작~종료·출력 수집. 최초와 반복은 별도 프로젝트 |
| F02 | 씬에 고정 ID 1,000개 생성 후 같은 좌표로 이동. 1/10/100개 요청에 분할 | 실제 이름·위치를 외부 Worker가 검사 | 이동 명령열 전체. 생성·최종 조회·검사 제외 |
| F03 | 1 KiB/64 KiB/1 MiB의 고정 payload | 크기·내용·요청·대상 일치 | CLI·전달·응답 수집 포함. 정답 파싱 제외 |
| F04 | 동일 C# 소스 수행 | 42·대상 정체성·소스 해시 | 도구별 입력·컴파일·실행·응답 경로 포함 |
| S01 | 고정 동시성의 명령 요청 | 기대 JSON·후속 Editor 상태 | 요청별 완료와 묶음 경과. 고정 도착률 아님 |
| 지연 감지 | 동일 Bridge F01의 B에만 대기 추가 | 실제 내부 기간·외부 기간·대상 | 제품 우열과 구분한 진단 |

UnityBridge는 버전 도움말에서 지원하는 전역 인수와 `call desk_probe --params …` 또는 exec 파일 입력을 사용한다. 공식 Unity CLI는 Pipeline의 사용자 명령으로 공통 본문을 실행한다. Go unity-cli는 자체 Connector에서 본문을 호출하고 exec의 동일 C#은 표준입력으로 받는다. 등록·입출력·연결 확인·컴파일러가 다르므로 논리 작업을 공유하는 전체 경로 비교이다.

Go의 전용 홈·대상 정보·업데이트 캐시는 측정 묶음 전에 준비한다. 실제 연결 확인·재시도·캐시 만료 후 조회는 원본 경로에 남는다. 자세한 조건은 [공식 비교](OFFICIAL-UNITY-COMPARISON.md), [Go 비교](GO-UNITY-COMPARISON.md), [CLI 호환성](CLI-COMPATIBILITY.md)에 있다.

F02 정답 검사는 fixture의 `Expected` 함수나 Unity가 반환한 true/false를 재사용하지 않는다. Worker와 독립 Python이 `x=i%100`, `y=i/100의 정수 몫`, `z=i%7`을 각각 계산한다. 직렬화 순서는 무관하며 거리 오차는 0.00001 미만이다. 관측 파일과 시행의 SHA-256을 연결한다. 관측 형식이 없는 과거 기록에 이 검증을 했다고 소급 표시하지 않는다.

이 작업들은 전달·응답 크기·분할·exec 경로를 설명한다. 모든 내장 명령, 게임 제작 생산성, AI 수행 능력을 대표하지 않는다. 실제 사용 사례 선정 자료와 프리팹·씬·컴포넌트별 독립 정답 기준이 추가로 필요하다. [SPEC 실행 규칙](https://www.spec.org/cpu2026/docs/runrules.html)의 작업·정답·보고 조건을 함께 명시하는 원칙을 참고했으며 SPEC 인증·점수와 관계없다.
