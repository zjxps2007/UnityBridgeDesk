# VM 속도 벤치 사용 가이드

이 문서는 **VM 개발 미리보기** 기준입니다. 실제 게스트 Unity 통합 시험 전이며, 현재 검증 범위는 [VM-PILOT.md](VM-PILOT.md)에 있습니다.

## 1. 기준 VM 준비

아직 VM이 없다면 앱의 준비 탭에 안내가 나타납니다.

1. 호스트에 [VirtualBox](https://www.virtualbox.org/wiki/Downloads)를 설치합니다.
2. 사용할 수 있는 [Windows 설치 이미지](https://www.microsoft.com/software-download/windows11)와 라이선스를 준비하고 Windows x64 VM을 만듭니다.
3. 게스트에 해당 VirtualBox 버전의 Guest Additions를 설치하고 재부팅합니다.
4. 게스트 Windows 사용자와 **계정 암호**를 준비합니다. Windows Hello PIN은 계정 암호가 아닙니다.
5. 게스트 Unity Hub에서 사용할 Editor를 기본 위치에 설치하고 활성화합니다. 앱에는 `6000.3.23f1`처럼 정확한 버전을 입력합니다.
6. 그 계정으로 Unity 실행과 종료가 가능한지 확인합니다. 실험 파일을 놓을 `C:\UnityBridgeBench` 폴더에 해당 계정의 쓰기 권한이 필요합니다. `Trial` 하위 폴더와 `input.zip`은 미리 만들지 않습니다.
7. VM의 공유 폴더를 해제하고 Windows를 **정상 종료**합니다. 저장된 실행 상태는 기준 상태로 사용하지 않습니다.

앱은 OS 설치나 Unity 로그인·활성화를 대신하지 않습니다. 현재 게스트 Editor 탐색은 `C:\Program Files\Unity\Hub\Editor\<버전>\Editor\Unity.exe` 형식을 사용합니다.

**가상머신 찾기 → 기준 VM 선택 → 시험용 복제 VM 만들기**를 누릅니다. 원본을 보존하고 전용 전체 복제본에 기준 스냅샷을 만듭니다. 디스크 복제와 해시 확인에는 시간이 걸릴 수 있습니다. 이후에는 같은 전용 VM을 복원해 사용합니다.

## 2. 릴리스와 실험 선택

**릴리스 새로 확인**은 공식 목록을 가져옵니다. Windows x64 CLI 자산이 있는 릴리스 2~8개를 선택합니다. **선택 버전 파일 준비**는 CLI와 Connector를 받아 검증·보관합니다. 시험 시작 시에도 필요한 파일을 준비합니다.

정식 버전의 단일 EXE와 RC의 ZIP을 모두 지원합니다. RC는 직접 선택하며 ZIP의 런타임 폴더 전체를 자동으로 준비합니다. 이전 목록에서 RC가 비활성화되어 있다면 새로 확인하세요. [RC 설치 변경과 RC1 보고 버전 오류](RC-INSTALL.md)에 동작을 설명했습니다. ZIP 해시는 ZIP과 대조하며 EXE·런타임 전체 해시를 별도로 고정합니다.

태그가 가리키는 커밋, 다운로드 주소, CLI SHA-256, Connector 폴더 해시를 기록합니다. GitHub가 제공하는 자산 SHA-256이 있으면 함께 대조합니다. 게시자 해시가 없으면 다운로드한 파일의 계산 해시를 고정하므로 같은 보증 수준은 아닙니다. 해시가 일치하는 보관본은 다시 다운로드하지 않습니다. **파일 준비 완료가 해당 Unity·릴리스 조합의 실행 호환성을 보증하지는 않습니다.**

기본은 F01, 독립 반복 N=2, 준비 호출 W=1, 반복 측정 M=3입니다. 두 버전으로 F01만 선택하면 첫 호출·반복 호출 두 조건을 각각 두 번 수행하므로 총 **8개 VM 시행**입니다. 정식 결론을 위한 권장 표본 수가 아니라 동작 확인용 작은 예비 설정입니다.

- **독립 반복 N**: 조건마다 VM을 복원해서 다시 시험하는 횟수.
- **준비 호출 W**: 측정 전에 보내는 동일 정책의 호출 수. F01 첫 호출에는 적용하지 않습니다.
- **반복 측정 M**: F01 반복 호출과 F03에서 한 시행 안에 측정하는 호출 수.
- **시드**: 버전 실행 순서를 재현하는 값.
- **벤치 설정 초기화**: 실험·횟수·제한 시간·시드를 기본값으로 복원합니다. VM·릴리스·계정 경로·결과는 유지합니다. 직전 초기화를 되돌릴 수 있습니다.

호스트의 개인 Unity 프로젝트는 입력받지 않습니다. 매 시행 게스트에 같은 최소 프로젝트와 벤치 도구를 새로 만듭니다.

## 3. 진행 확인

게스트 계정·암호와 Unity 버전을 입력하고 **예비 시험 시작**을 누릅니다. 다른 VirtualBox VM은 종료해야 합니다.

진행 탭은 현재 단계와 기록을 보여줍니다.

1. 기준 이미지·VM 소유 표식·고정 설정 확인
2. 기준 스냅샷 복원과 파일 전달
3. 게스트 Windows 연결, Unity 기동·컴파일·Connector ready 대기
4. 준비 단계의 네트워크 연결 차단 확인
5. 게스트가 측정 허가를 받은 뒤 고정 명령 실행·응답 검증
6. 결과 수집, VM 종료와 기준 스냅샷 복원

패키지 의존성을 준비할 수 있도록 준비 단계에는 NAT 연결을 허용합니다. ready 이후에는 가상 네트워크 케이블을 끊고, 끊김을 확인한 뒤에만 측정을 허가합니다. 측정 중 호스트와 파일을 주고받지 않습니다.

**중단**을 누르면 시험 VM 정리를 시도합니다. 진행 중 창을 닫아도 정리를 기다립니다. 복원이 실패하면 다음 시행을 실행하지 않고 결과에 표시합니다. 앱·호스트 강제 종료 후의 자동 복구는 아직 검증하지 않았으므로 다시 실행하기 전 전용 VM 상태를 확인해야 합니다.

게스트 암호는 설정 JSON이나 명령 인수 본문에 넣지 않습니다. 실행 중 VirtualBox 전달용 임시 파일을 사용하고 정상 종료·중단 처리에서 삭제합니다. 호스트 강제 종료 시 임시 파일이 남을 수 있습니다. 개인 데이터 폴더 전체를 공유하지 마세요.

## 4. 결과 확인

완료 후 결과 탭에서 다음 순서로 봅니다.

1. **계획·수행·성공·실패/중단·미수행 수**를 확인합니다.
2. 같은 실험·조건의 평균과 중앙값, 성공한 독립 시행 수를 비교합니다.
3. 버전 비교는 같은 블록에서 두 버전이 모두 성공한 시행만 사용합니다.
4. 실패 항목의 이유와 VM 복원 확인 여부를 봅니다.
5. **JSON·CSV 폴더 열기**로 원시 자료를 확인합니다.

`run.json`에는 계획·조건·버전 해시·VM 설정·결과가 있습니다. 시행별 파일에는 요청·준비 응답·게스트 표본을 남깁니다. `samples.csv`에는 실패와 미수행도 상태로 기록하며 누락 시간을 0으로 바꾸지 않습니다.

단위는 ms입니다. F01·F03의 시행 대표값은 호출 시간의 평균, F02는 전체 명령열을 완료한 시간입니다. 한 시행의 반복 호출을 서로 독립된 VM 시행으로 세지 않습니다. 현재 화면은 예비 기술 통계이며 신뢰구간·p95·전체 승자를 표시하지 않습니다.

**현재 폴더 열기는 익명화 내보내기가 아닙니다.** 원시 JSON에는 개인 VM 경로 등이 들어갈 수 있으므로 공개 전 내용을 확인하세요. 이전 버전 결과는 별도 폴더로 열며 새 VM 결과와 합산하지 않습니다.

## 문제 해결

| 표시·상황 | 확인할 항목 |
|---|---|
| VirtualBox를 찾지 못함 | 설치 후 가상머신 찾기. 별도 설치 위치는 고급 설정에서 VBoxManage.exe 선택 |
| VM 목록 없음 | Windows 기준 VM을 먼저 생성 |
| 기준 VM 준비 실패 | 정상 종료 여부, 공유 폴더·외부 디스크 연결, 저장 공간 확인 |
| 게스트 연결 시간 초과 | Guest Additions, Windows 계정 이름과 실제 암호 확인 |
| Unity 준비 실패 | 게스트 Editor 버전·활성화·실험 폴더 쓰기 권한·패키지 준비 연결 확인 |
| 다른 VM 실행 중 | 다른 VirtualBox VM을 종료하고 재시도 |
| 기준 디스크·설정이 바뀜 | 수정된 기준을 섞지 말고 원하는 조건으로 새 시험용 복제 VM 준비 |
| 복원 실패 | 다음 시행이 중단됨. 전용 VM 상태를 해결한 뒤 새 시험 시작 |
| Worker 런타임 없음 | Publish-Desk.ps1로 만든 자체 런타임 포함 패키지 사용 |

기존 배포본 안내: [이전 사용 가이드](LEGACY-USAGE.md) · [이전 측정 명세](LEGACY-BENCHMARKS.md).
