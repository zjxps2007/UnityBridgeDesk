# 캐릭터 크기 보정과 리틀 모델 엔진 분리

2026-09-20. 같은 크기의 표시 영역을 사용해도 아샤가 작게 보이던 문제를 수정하고, 독립 앱을 리틀 모델 엔진으로 구분한다.

## 크기와 착지선

아라 원본의 서 있는 그림 높이는 약 426px이다. 아샤는 걷기 행에서 약 304px, 대기 행에서 약 285px이다. 이전에는 투명 여백이 포함된 칸을 각각 화면에 맞췄기 때문에 실제 키가 달랐다.

이제 기준 키를 메타데이터로 두고 `표시 영역 크기 × 0.84 / 원본 기준 키`로 그림을 확대·축소한다. 각 포즈의 신발 밑면을 `표시 영역 높이 × 0.89`에 배치해 기존 물리 착지점과 맞춘다. 메시는 동일한 원본 좌표를 사용하고, 그리기 영역만 보정한다. 이동 속도나 벤치 명령·측정·통계는 변경하지 않는다.

수면처럼 원래 낮은 포즈를 개별 높이에 맞춰 확대하지 않는다. 같은 행의 서 있는 기준 크기를 사용하므로 웅크린 자세가 자연스럽게 낮아진다. PNG 원본은 편집하지 않았다.

## 앱의 독립성

- 제품·창·알림 영역: **리틀 모델 엔진**. 실행 파일: **LittleModelEngine.exe**.
- 자체 `Characters/`·`Assets/`를 소유하며 Desk 소스를 링크하거나 빌드 때 복사하지 않는다.
- 설정·단일 실행 잠금·어셈블리 이름은 `LittleModelEngine`으로 구분한다. Desk와 이전 AraAshaCompanion 설정은 자동으로 가져오거나 덮어쓰지 않는다.
- Desk Worker 프로세스 조회와 자동 정지를 제거한다. 한 앱의 실행·종료·벤치·캐릭터 설정 변경이 다른 앱을 제어하지 않는다.
- 이번 크기 보정은 양쪽에 각각 적용했다. 이후 그림·행동 변경은 요청받은 앱에만 적용한다.

물리적 프로젝트 경로 `src/UnityBridgeDesk.Companion`은 스크립트 호환을 위해 유지하지만, 앱 코드의 네임스페이스는 `LittleModelEngine`이다. 이전 실행 파일과 데이터는 자동 삭제하지 않는다.

## 적용한 디자인 원칙

`design/UI-DESIGN-WORKFLOW.md`, `docs/CHARACTERS.md`, `docs/ASHA-CHARACTER-DISTINCTION.md`를 확인했다. 앞서 읽은 frontend-design의 캐릭터 실루엣 구분과 UI/UX Pro Max의 공간적 연속성 원칙을 결합한다. 두 종의 헤어·의상·꼬리 차이는 유지하면서, 크기와 착지 기준의 일관성을 바로잡는다. 웹용 카드·장식·추가 모션은 도입하지 않는다. 새 디자인 스킬 설치나 이미지 생성은 수행하지 않았다.

## 확인 방법

실제 WPF에서 두 캐릭터의 8개 프레임을 크기 96/112/144 DIP와 배율 100/150/200%로 렌더링한다. 알파값 192를 넘는 픽셀의 경계를 측정해, 서 있는 포즈의 키 차이 2 DIP 이내와 신발·착지선 오차 1.5 DIP 이내, 가장자리 잘림 없음, 수면 비율 유지를 확인한다. `character-scale.csv`를 검사 증거 폴더에 남긴다.

독립 앱의 자가 검사는 실제 투명 창과 설정 화면을 화면 밖에서 열고, 창 스타일·클릭 통과·낙하·착지·정상 종료를 확인한다. 실행 어셈블리에 Desk 프로젝트 의존성이 없는지도 검사한다. Desk 준비 화면과 두 크기의 독립 앱 설정 화면을 실제로 렌더링해 검토한다. 이 검사는 사용자의 열린 프로그램이나 실제 Unity 벤치를 조작하지 않는다.
