# Desk의 발판 인식과 접촉 계산

2026-09-20 · Desk v0.4.0 후속 수정이다. 아라와 아샤에 함께 적용한다. 리틀 모델 엔진은 별도 앱이며 이번 수정 범위에 포함하지 않는다.

## 문제와 변경

기존 구현도 화면 도형을 읽었지만 발판 위 목적지를 약 40 DIP 간격으로 뽑은 뒤 몸이 들어갈 수 있는지 검사했다. 좁은 빈 공간이 표본 사이에 있으면 유효한 자리가 사라졌다. 일부만 보이는 줄이나 버튼을 통째로 제외하고, 둥근 버튼의 사각형 경계를 평평한 윗면으로 취급하는 문제도 있었다. 화면 갱신을 기다리는 동안 과거 발판이 잠시 남을 수 있었다.

현재는 **화면의 윗면 → 연속된 착지 가능 구간 → 접촉 검사 → 이동 경로** 순서로 계산한다. 경로 탐색은 유한한 후보를 사용하지만, 서 있는지·걸을 수 있는지·어디에 착지하는지는 후보 좌표에 의존하지 않는다.

## 화면에서 도형을 얻는 방법

- 글자는 WPF가 그린 글리프를 같은 기준선의 줄로 합친다. 실제 줄바꿈·정렬·크기·말줄임을 반영한다. 문단이나 클릭 영역 전체를 바닥으로 만들지 않는다.
- 버튼은 실제 채워진 도형과 테두리의 평평한 윗부분을 읽는다. 둥근 모서리의 빈 부분은 제외한다. 투명한 버튼은 안쪽 글자와 기호를 별도로 읽는다.
- 선택 상자(`ComboBox`)와 입력칸(`TextBoxBase`, `PasswordBox`)도 실제 외곽 프레임의 윗면을 읽는다. 이 종류를 장애물로만 등록해 자유 낙하가 통과하던 누락을 수정했다. 값·화살표·커서·드롭다운 항목을 별도 발판으로 중복 등록하지 않는다. 목록·표의 내부 셀과 스크롤바는 기존 보호 규칙을 유지한다.
- 그래프는 `SpeedChartView`가 그릴 때 계산한 막대와 바닥 좌표를 받는다. 데이터·막대 높이·버전 순서는 변경하지 않는다.
- 모두 캐릭터 레이어의 DIP 좌표로 변환하고 스크롤 및 상위 요소의 가림을 반영한다. 옆이 잘리면 남은 구간을 사용한다. 원래 윗면이 잘렸다면 스크롤 경계에 새 발판을 만들지 않는다.

## 연속 구간과 접촉

캐릭터 크기를 `W × H`, 왼쪽 위 좌표를 `(x, y)`라고 한다. 그림의 투명 여백을 제외한 발 높이는 `y + 0.89H`, 두 발의 지지 폭은 `[x + 0.35W, x + 0.65W]`이다. 발판이 `[L, R]`, 높이가 `Y`이면 서 있을 수 있는 좌표는 다음 범위이다.

```text
y = Y - 0.89H
L - 0.35W ≤ x ≤ R - 0.65W
```

여기에 화면 경계와 몸의 충돌 조건을 적용한다. 몸 높이와 겹치는 장애물의 가로 영역을 캐릭터 폭만큼 확장하여 해당 x 구간을 빼낸다. 남는 구간이 매우 짧더라도 보존한다. 발판 위의 기존 3 DIP 띄우기를 없애고 실제 윗면 높이에 발을 맞춘다. 내용 가림 방지를 위한 장애물의 좌우 여유는 유지한다.

걷기는 출발부터 도착까지 지지 구간이 끊기지 않는지 확인한다. 낙하는 이전 발 위치와 다음 발 위치 사이를 가로지르는 모든 발판 중 첫 유효 접촉을 구한다. 비스듬한 하강에서는 접촉 시점의 x도 보간한다. 따라서 빠른 이동이 얇은 발판을 건너뛰거나 일정 간격의 착지점으로 가로 위치를 바꾸지 않는다. 떠오르는 중에는 위쪽 발판에 착지하지 않는다.

자율 점프는 기존 곡선 경로와 몸의 장애물 검사를 유지한다. 실행 중에는 다음 위치와 내려오는 발의 접촉을 다시 검사한다. 목적지가 사라지거나 길이 막히면 과거 목적지로 순간 이동하지 않고, 현재 지지가 없을 때 자유 낙하로 이어진다.

## 화면 변경과 복구

레이아웃·스크롤·그래프 변경을 모아 WPF 그리기 이후 지도를 갱신한다. 이동 프레임 전에 변경 표시가 남으면 먼저 갱신한다. 예전 0.7초 대기 간격을 사용하지 않는다. 도형·화면 경계·캐릭터 크기가 동일하면 지도와 연결 계산을 재사용한다.

지지가 사라지면 떨어지고 두 발과 몸이 들어갈 수 있는 첫 발판에 착지한다. 충분한 공간이 없는 줄 사이나 너무 짧은 글자는 바닥으로 쓰지 않는다. 아래에 발판이 전혀 없으면 화면 아래로 내려온 뒤 다른 유효 발판을 찾고, 아무 자리도 없으면 숨는다. 빈 화면에서 낙하를 반복하지 않으며 실제 발판이 다시 생기면 복귀한다.

움직임 끄기·설정 팝업·벤치 중 정지 조건은 유지한다. 정지가 요청되면 안전한 자리로 정리하므로 이때는 낙하 애니메이션을 강제로 재생하지 않는다.

## 적용 범위와 검증

이 계산은 Desk 안의 수평 발판을 위한 2D 접촉 모델이다. 픽셀 단위 지형, 임의의 곡면을 걷는 물리 엔진, 두 캐릭터 사이의 충돌은 구현하지 않는다. 글줄은 글자마다의 굴곡이 아닌 줄의 윤곽 영역을 사용한다. 상위 클립의 경계는 사각형 기준이며 회전·기울어진 요소는 발판으로 제외한다.

회귀 검사는 좁은 공간, 표본에 없는 착지점, 작은 발판 틈, 비스듬한 낙하, 크기 변경을 다룬다. 실제 WPF 검사에서는 한글 줄·둥근 버튼·일부 가려진 막대, 버튼 이동, 프로그램에 의한 스크롤, 발판 없는 화면과 복귀를 확인한다. 아라와 아샤 각각의 착지선과 기존 클릭·키보드·100/150/200% 배율 검사도 포함한다. 시험 화면의 그래프는 합성 데이터이며 Unity 실험을 새로 실행하지 않는다.

선택 상자 누락은 실제 `BenchControls.xaml`을 사용해 Unity 안내문·버전 선택·다시 찾기·직접 선택·실험 환경 접기 메뉴의 배치를 재현했다. 수정 전 `EditorList` 발판 부재로 실패하는 것을 확인한 뒤, 두 캐릭터의 낙하·선택 상자와 입력칸 착지·세 배율 렌더링·드롭다운 선택·텍스트 선택·가림·비활성화·다시 표시를 검사한다. 착지는 두 발과 몸의 공간이 확보되는 구간에 한하며 위쪽 글자나 다른 컨트롤을 덮는 자리는 자율 목적지에서 제외한다.

코드: `AshaMap.Contact.cs`가 연속 구간·접촉을 계산하고, `AshaCompanion.Geometry.cs`·`AshaTextLayout.cs`·`AshaPaintedGeometry.cs`·`AshaCompanion.Charts.cs`가 화면 도형을 수집한다. `AshaCompanion.cs`와 낙하 전용 파일이 지도 갱신·이동·숨김 상태를 연결한다.

작업 기준으로 `AGENTS.md`, [디자인 작업 기준](../design/UI-DESIGN-WORKFLOW.md), [글줄 발판](ASHA-FINE-SURFACES.md), [자유 낙하](ASHA-FALLING.md), [모션](MOTION.md)을 읽었다. 이번 작업은 접촉 계산 수정이며 별도 외부 디자인 스킬을 실행하거나 새 스타일을 도입하지 않았다. 입력 우선·내용 가림 방지·공간적 연속성과 정지 설정을 유지한다.
