> 이전 기록은 좌측 **실행 기록**에서 검색한 뒤 **선택한 결과 열기** 또는 Enter로 연다. 결과 조회와 벤치 설정 재사용은 별개이다.

# 결과 읽기와 파일 저장

평균 차이와 함께 **감소율 95% 신뢰구간**을 읽는다. 0%가 구간에 들어가면 방향이 불확실하다. 5쌍 미만은 표본 부족, 제외가 있으면 성공쌍에 한정, 미완료 기록은 판단 유보로 표시한다. **기준 버전 대비 → 측정 신뢰도와 다음 실험**에서는 분산·비용과 반복 수 제안, 버전별 시행 순서를 확인한다. **시행 상세 → 호출 순서**는 사전 실행과 측정의 변화를 구분한다. [수식·가정·사용 절차](STATISTICAL-METHODOLOGY.md)

좌측 **실행 기록**을 눌러 전용 목록에서 날짜·버전·상태로 검색한다. 기록 선택 후 **선택한 결과 열기** 또는 Enter·더블클릭으로 연다. 처음 연 기록은 **전체 결과** 비교표로 시작하고, 같은 창에서 다시 열면 이전의 조건·필터·시행 선택·보기를 복원한다. **설정 재사용**은 실험 조건·버전·기준 버전·Unity 경로를 준비 탭으로 가져오며 실행은 시작하지 않는다. 설치되지 않은 Unity나 목록에 없는 버전은 다시 확인해야 한다. 중앙 상단에는 **설정 재사용**과 **내보내기**만 둔다. **시험 요약 · 환경과 성공·실패 수**를 펼치면 전체 판정과 환경을 읽는다.

| 메뉴 | 동작 |
|---|---|
| 내보내기 → 비교 요약 TXT 열기 | 평균 시간 차이를 설명하는 메모와 상세 수치가 담긴 파일을 연다. |
| 내보내기 → 비교 요약 복사 | 짧은 비교 메모만 클립보드로 복사한다. |
| 내보내기 → 분석 Excel 열기 | 기존 다섯 시트와 측정신뢰도·반복설계·사전실행을 포함한 여덟 시트로 연다. |
| 내보내기 → 보고서 폴더 열기 | 요약 TXT·분석 Excel·실패 내역·SVG 그래프·측정근거 TXT가 있는 폴더를 연다. |
| 내보내기 → 현재 그래프 SVG 저장 | 선택한 조건과 지표만 SVG 이미지로 저장한다. 조건·단위·유효 횟수·측정 설정이 포함된다. |
| 내보내기 → 원본·로그 폴더 열기 | 현재 선택한 시험의 JSON·CSV·전체 로그가 있는 폴더를 연다. |

메뉴 버튼은 클릭하거나 키보드로 포커스를 둔 뒤 Enter·Space·아래 화살표로 연다. 메뉴 항목은 방향키로 선택하고 Enter로 실행한다. Escape 또는 바깥 클릭으로 닫는다. 기록 선택 목록 옆의 새로고침은 기록 목록만 다시 읽으며 새 벤치를 실행하지 않는다.

## 비교 메모

메모는 조건별로 빠른 버전, 두 버전의 평균, 시간 차이와 완료 시간 감소율을 표시한다. 다음은 실제 결과가 아닌 문장 형식의 예시다.

> F01 반복 명령 평균 시간: vB 버전이 vA 버전보다 호출당 평균 20.00 ms 빨랐다. 평균은 vB 80.00 ms, vA 100.00 ms이며, vA 대비 완료 시간이 20.0% 짧았다(공동 유효 2/2블록).

같은 조건·블록에서 양쪽 모두 유효한 시행만 사용한다. 실패나 미수행을 0ms로 넣지 않는다. 한 블록만 비교했다면 반복 간 변동을 확인하지 못했다고 표시하고, 유효한 평균을 확보하지 못한 조건은 비교 불가로 설명한다. 평균이 같거나 표시 정밀도 내 차이라면 빠른 버전을 임의로 고르지 않는다.

메모는 빠른 버전을 먼저 쓰므로 감소율의 분모는 문장에 적힌 느린 버전의 평균이다. 예를 들어 기준이 100ms, 후보가 150ms이면 기준이 후보보다 33.3% 짧다고 쓴다. 반면 기준 대비 비교 표는 후보 시간이 기준보다 50% 증가했다고 표시한다. 분모와 비교 방향이 다른 표현이다.

서로 다른 실험의 시간을 합산해 전체 순위를 만들지 않는다. F01·F03·F04·S01은 호출당 시간, F02는 전체 작업 완료 시간으로 설명한다. 메모는 이번 측정의 관찰값이며 통계적 성능 우열을 확정하지 않는다.

## 앱에서 확인

새 기록은 **전체 결과** 표에서 조건별 차이를 먼저 읽는다. 기준·대상 평균은 같은 블록에서 양쪽 모두 유효한 쌍을 사용한다. 유효/계획 쌍 수와 단위를 함께 확인한다. 한 쌍은 반복 변동을 확인할 수 없으며, 조건들을 합쳐 전체 성능 순위를 만들지 않는다. 행을 선택하면 아래의 조건별 화면으로 이동한다. **전체 결과** 버튼으로 표에 돌아간다.

1. 좌측에서 **실험(F01~S01) → 조건**을 선택한다. 선택 조건은 중앙의 세 결과 화면에서 공유한다. 시행 번호와 실험 코드는 서로 다른 단위다.
2. **조건별 시간**은 후보·기준 이름, 평균 시간 차이·공동 유효 쌍 수·통계 포함/제외 수를 먼저 표시한다. 세로 막대 위에 평균, 아래에 버전과 유효/계획 횟수를 표시한다. 평균·중앙값 표와 측정 조건 설명은 펼쳐 본다. 상단 차이는 두 대상 모두 유효한 블록의 평균으로 계산하므로, 각 대상의 전체 유효 시행을 사용하는 그래프와 다를 수 있다. 이 구분은 그래프 위에 항상 표시한다. 한 쌍만 유효하면 반복 변동 확인 전이라고 표시한다. 후보가 여럿이면 임의의 전체 우승자를 만들지 않고 기준 대비 화면으로 안내한다.
3. **기준 버전 대비**는 같은 실험에서 두 버전 모두 유효한 쌍만 비교한다. 평균 시간 증감, 비교 쌍 수와 제외 쌍 수를 짧은 문장으로 먼저 보여준다.
4. 좌측의 **개별 시행** 목록에서 `#39`처럼 원래 번호를 고르면 중앙에 해당 시행의 상세를 표시한다. 검색칸의 숫자나 `#번호`는 정확한 시행 번호로 찾고, 버전명·상태는 부분 검색한다. 검색·필터 후에도 번호를 다시 매기지 않는다. **시행 표로 보기**를 펼치면 여러 시행의 수치를 표로 비교한다.
5. 막대를 누르면 해당 버전의 **시행 상세**로 이동한다. 좌측 **버전·상태 필터**로 더 좁힐 수 있다. **이 시행의 로그 열기**는 해당 시행의 로그만 연다. **제외된 시행 확인**은 현재 조건의 실패·정리 실패·중단·미수행을 모아 보여준다. **필터 초기화**는 버전·상태·검색어를 해제하며 선택한 실험 조건을 유지한다.

내보내기와 설정 재사용은 중앙 상단에 유지한다. 좁은 창의 좌측 목록은 기본으로 접히며 **목록** 또는 `Alt+0`으로 펼칠 수 있다. 직접 전환한 접기·펼치기 상태는 다음 실행에도 복원한다. 시계는 작게 상단에 배치한다. 좌측의 조건·필터와 시행 목록, 중앙 결과는 각각 스크롤한다. 검색 입력은 고정하고 필터를 모두 펼쳐도 시행 목록의 공간을 남긴다.

그래프는 포인터를 올리면 버전·시간·유효 횟수와 상세 이동 안내를 표시한다. 방향키로 버전을 고르고 Enter·Space로 상세를 열 수도 있다. 버전이 많아 창 너비를 넘으면 그래프를 가로로 스크롤한다. 긴 시행 표 끝에서는 마우스 휠이 바깥 화면으로 이어진다. 상세의 이전/다음 시행은 현재 필터 범위에서 이동하며, 조건 그래프로 돌아가기 버튼을 제공한다. 결과 보기마다 세로 스크롤을 기억한다. 전체 결과 표에서는 특정 조건의 SVG 저장을 비활성화하고, 조건을 열면 다시 사용할 수 있다.

기준 버전은 준비 화면의 **비교 기준**에서 명시적으로 지정한다. 선택 항목에 ‘기준’ 표시를 붙이며 새 기록에는 기준을 첫 번째 릴리스로 저장한다. 과거 기록은 원래 저장된 기준을 유지한다. 개별 버전 평균은 해당 버전의 유효 시행 전체로, 두 버전의 비교는 같은 블록에서 양쪽 모두 유효한 시행으로 계산하므로 두 화면의 평균이 다를 수 있다.

**첫 명령 완료 시간**은 새 Unity가 ready가 된 뒤 사전 실행 없이 명령 1회를 측정한다. **반복 명령 평균 시간**은 다른 새 프로젝트에서 W회 사전 실행을 제외한 뒤 M회 명령을 측정해 평균한다. 화면과 TXT에 실제 W·M 및 프로젝트 실험 횟수를 표시한다. W=0이면 그대로 0회라고 표시한다. 각 CLI는 새 프로세스이며 Unity 시작 시간은 두 조건 모두 제외한다.

`완료`는 실행이 끝났다는 뜻이다. 실패가 있으면 `완료 — 실패 N건 포함`으로 표시한다. 과거 `running` 기록은 실행 여부를 단정하지 않고 `실행 상태 확인 필요`로 표시한다.

## 그래프와 안정성

아샤 표시·탐색이 켜져 있으면 결과 막대를 발판으로 삼아 가끔 뛰어논다. 그래프 위쪽에는 착지와 도약을 위한 여유 공간을 둔다. 접근·놀이 중에는 수치를 막대 안쪽 또는 옆으로 표시하고 떠나면 원래 위치로 되돌린다. 값·버전 순서·색·축 상한과 보고서 수치는 그대로이다. 마우스 입력은 그래프에 통과하며 조작하면 놀이를 멈춘다. 원하지 않으면 **설정 → 아샤 → 탐색 끄기 / 숨기기**로 제어한다. [그래프 놀이](ASHA-CHART-PLAY.md)

**조건별 시간**에서 조건을 선택하고 평균 완료 시간·유효 완료율을 전환한다. 시간 막대는 해당 버전의 유효 시행 평균이다. 최소·최대·표준편차는 시행 상세에 분리한다. 조건마다 시간 축 범위가 다르다. 완료율 축은 0~100%다. 표본이 없으면 ‘유효 측정 없음’으로 표시한다.

버전은 실행 기록에 저장된 **기준 버전 → 나머지 선택 버전** 순서로 고정한다. 조건과 지표가 달라져도 같은 버전의 위치와 색이 유지되며 SVG도 같은 기준을 쓴다. 실패·미수행으로 측정값이 없어도 그 버전의 자리는 유지한다. 실제 측정 순서의 회전은 표시 순서에 영향을 주지 않는다.

시행 상세의 **안정성 요약**은 접어서 둘 수 있다. 유효 완료 / 평가 대상 시행, 개별 호출 판정, 시간 초과·응답 불일치·정리 실패, 범위·표준편차·성공 호출 P95, 부하 처리량을 표시한다. 환경 준비 실패·벤치 호환성 오류, 사용자 중단·미수행은 완료율 분모에서 제외한다. 정리 실패는 포함한다. 시행 종료 수와 평가 대상 수는 다를 수 있다. 구버전의 없는 판정은 추정하지 않는다. 호출이 성공했어도 시행의 최종 상태·정리는 실패할 수 있다. 계산식과 고부하 시험 범위는 [STABILITY.md](STABILITY.md)에 명시한다.

## 결과 폴더

벤치가 끝난 뒤 측정 밖에서 읽기용 파일을 만든다. 저장된 과거 결과는 **내보내기**의 TXT·Excel·보고서 폴더 항목을 누르면 재실험 없이 생성한다.

```text
speed/reports/
└─ 2026-09-16_002552__3개버전__실행ID/
   ├─ 00_결과요약.txt
   ├─ 01_결과분석.xlsx
   ├─ 02_실패내역.txt
   ├─ 03_결과그래프.svg
   └─ 04_측정근거.txt
```

- **결과요약.txt**: 조건별 평균 시간 차이를 설명하는 메모를 먼저 읽고, 수행 현황·상세 수치·읽는 기준을 확인한다.
- **결과분석.xlsx**: 결과요약 / 블록비교 / 시행기록 / 호출표본 / 안정성 / 측정신뢰도 / 반복설계 / 사전실행의 여덟 시트. 숫자와 빈칸을 구분하고 필터·행/열 고정을 제공한다.
- **실패내역.txt**: 실패·제외 시행의 확인된 현상과 정리 상태. 직접 원인은 로그 근거 없이 단정하지 않는다.
- **결과그래프.svg**: 모든 조건의 세로 시간 막대와 유효/계획 횟수. 브라우저에서 열거나 문서에 넣을 수 있다.
- **측정근거.txt**: 분석 규칙·논문·수식·전제와 조건별 구간·반복 수 제안. 다른 사람에게 측정 방법을 공유할 때 함께 보낸다.

요약과 실패 내역은 UTF-8 BOM 텍스트다. Excel 파일은 저장 시점의 분석 사본이며, 셀을 편집해도 Desk 원본이나 집계 숫자가 자동 갱신되지는 않는다. 정렬·필터·추가 수식은 사본에서 사용할 수 있다. 파일 생성에 Excel 설치는 필요하지 않고, 열 때는 XLSX를 지원하는 프로그램이 필요하다.

F01·F03·F04·S01의 단위는 `ms/호출`, F02는 `ms/전체 작업`이다. 실패와 미수행을 0ms로 바꾸지 않는다. 개별 호출에 반복된 시행 대표시간을 평균 내지 않도록 시행과 호출을 다른 시트로 나눈다.

기존 JSON·CSV·로그는 `speed/local-runs/<실행 ID>`에 그대로 남는다. **내보내기 → 원본·로그 폴더 열기**로 열 수 있다. 결과 폴더 안의 숨김 파일 `.report.json`에는 형식 버전, 생성 시각, 원본 기록을 직렬화한 스냅샷의 해시와 보고서 파일 해시가 들어 있다.

동일한 기록·파일은 재사용한다. 기록이 바뀌었거나 사용자가 보고서를 편집했다면 `사본-N` 폴더에 새 파일을 만들어 이전 파일을 보존한다. 보고서 저장에 실패하면 재시도 안내를 표시하며, 이 문제를 벤치 실패로 기록하지 않는다. Excel 한 시트의 최대 행 수를 넘는 경우에는 원본 자료를 사용하도록 안내한다.

## 구현 기준

현재 보고서 형식은 8이다. 이전 보고서는 원본 기록에서 새 사본으로 생성한다. 그래프의 버전 순서를 고정하고, 시행 상세에 호출 수·첫 실패 순서를 표시한다. 구조화된 연결 검색 오류가 남아 있으면 JSON 파싱 오류 대신 실제 의미를 표시한다. 미지원 옵션 --no-update-check 오류 원문이 남은 기록은 벤치 호환성 오류로 분류한다. 원본 판정과 시간은 바꾸지 않고 파생 보고서의 완료율 평가 분모에서 분리한다. 원본 기록과 이전 보고서 파일은 덮어쓰지 않으며 벤치를 다시 실행할 필요는 없다.

공식 Unity 비교의 새 기록에는 **공식 CLI·Pipeline 임시 보관함 삭제 확인** 또는 **정리 미확인**을 표시한다. 시행별 프로젝트 정리와 벤치 전체의 다운로드 원본 정리는 별개다. 원본 삭제 실패가 있으면 측정이 성공했더라도 실행 전체를 정리 실패로 표시한다. 삭제 완료 기록이 없는 과거 실행에 삭제 성공을 추정해 붙이지 않는다.

앱·TXT·Excel은 공통 `SpeedReport` 집계 모델을 사용한다. 유효성은 `SpeedAnalysis.IsValid`로 공유한다. 파일은 임시 폴더에서 모두 작성한 뒤 보고서 폴더로 옮기므로 작성 중 파일을 완성본으로 보여주지 않는다.

XLSX 출력은 .NET의 ZIP·XML 기능을 사용하며, 표준 SpreadsheetML의 통합 문서·시트·스타일 관계를 따른다. 외부 패키지나 Office 자동화에 의존하지 않는다. [Microsoft: SpreadsheetML 문서 구조](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document)
