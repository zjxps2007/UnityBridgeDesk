# 결과 읽기와 파일 저장

결과 탭의 상단은 짧은 메모다. 완료 상태, 성공·실패·중단·정리 실패·미수행, 유효 시행 수와 기준 버전을 먼저 확인한다. **요약 복사**는 발표나 질문에 붙여 넣을 수 있는 짧은 글을 복사한다.

## 앱에서 확인

1. **조건별 시간**에서 실험·조건·버전별 평균과 중앙값, 유효/계획 수를 본다.
2. **기준 버전 대비 비교**에서 시간 증가·감소와 공동 유효 블록 수를 확인한다.
3. 조건별 표의 행을 선택하면 해당 조건의 시행 목록이 표시된다.
4. 시행 목록은 실험·버전·상태로 좁힐 수 있다. 실패와 중단, 정리 실패, 미수행을 따로 고른다.
5. 시행을 선택하면 확인된 오류와 통계 제외 이유를 읽을 수 있다. 로그가 존재하면 **선택 시행의 로그**로 연다.

기준 버전은 실행 기록에 저장된 첫 번째 릴리스다. 개별 버전 평균은 해당 버전의 유효 시행 전체로, 두 버전의 비교는 같은 블록에서 양쪽 모두 유효한 시행으로 계산한다. 따라서 두 표의 평균이 다를 수 있다.

`완료`는 실행이 끝났다는 뜻이다. 실패가 있으면 `완료 — 실패 N건 포함`으로 표시한다. 과거 `running` 기록은 실행 여부를 단정하지 않고 `실행 상태 확인 필요`로 표시한다.

## 결과 폴더

벤치가 끝난 뒤 측정 밖에서 읽기용 파일을 만든다. 저장된 과거 결과는 **엑셀 열기** 또는 **결과 폴더**를 누르면 재실험 없이 생성한다.

```text
speed/reports/
└─ 2026-09-16_002552__3개버전__실행ID/
   ├─ 00_결과요약.txt
   ├─ 01_결과분석.xlsx
   └─ 02_실패내역.txt
```

- **결과요약.txt**: 상태, 건수, 조건별 시간, 기준 대비 변화와 읽는 기준.
- **결과분석.xlsx**: 결과요약 / 블록비교 / 시행기록 / 호출표본의 네 시트. 숫자와 빈칸을 구분하고 필터·행/열 고정을 제공한다.
- **실패내역.txt**: 실패·제외 시행의 확인된 현상과 정리 상태. 직접 원인은 로그 근거 없이 단정하지 않는다.

요약과 실패 내역은 UTF-8 BOM 텍스트다. Excel 파일은 저장 시점의 분석 사본이며, 셀을 편집해도 Desk 원본이나 집계 숫자가 자동 갱신되지는 않는다. 정렬·필터·추가 수식은 사본에서 사용할 수 있다. 파일 생성에 Excel 설치는 필요하지 않고, 열 때는 XLSX를 지원하는 프로그램이 필요하다.

F01·F03의 단위는 `ms/호출`, F02는 `ms/전체 작업`이다. 실패와 미수행을 0ms로 바꾸지 않는다. 개별 호출에 반복된 시행 대표시간을 평균 내지 않도록 시행과 호출을 다른 시트로 나눈다.

기존 JSON·CSV·로그는 `speed/local-runs/<실행 ID>`에 그대로 남는다. **원본 자료**로 열 수 있다. 결과 폴더 안의 숨김 파일 `.report.json`에는 형식 버전, 생성 시각, 원본 기록을 직렬화한 스냅샷의 해시와 보고서 파일 해시가 들어 있다.

동일한 기록·파일은 재사용한다. 기록이 바뀌었거나 사용자가 보고서를 편집했다면 `사본-N` 폴더에 새 파일을 만들어 이전 파일을 보존한다. 보고서 저장에 실패하면 재시도 안내를 표시하며, 이 문제를 벤치 실패로 기록하지 않는다. Excel 한 시트의 최대 행 수를 넘는 경우에는 원본 자료를 사용하도록 안내한다.

## 구현 기준

앱·TXT·Excel은 공통 `SpeedReport` 집계 모델을 사용한다. 유효성은 `SpeedAnalysis.IsValid`로 공유한다. 파일은 임시 폴더에서 모두 작성한 뒤 보고서 폴더로 옮기므로 작성 중 파일을 완성본으로 보여주지 않는다.

XLSX 출력은 .NET의 ZIP·XML 기능을 사용하며, 표준 SpreadsheetML의 통합 문서·시트·스타일 관계를 따른다. 외부 패키지나 Office 자동화에 의존하지 않는다. [Microsoft: SpreadsheetML 문서 구조](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document)
