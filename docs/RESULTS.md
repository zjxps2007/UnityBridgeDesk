# 결과 읽기와 파일 저장

결과 탭의 상단에서 완료 상태, 성공·실패·중단·정리 실패·미수행, 유효 시행 수와 기준 버전을 확인한다. 상단 동작은 **요약 메모**, **분석 Excel 열기**, **자료 폴더**의 세 묶음으로 구분한다.

| 메뉴 | 동작 |
|---|---|
| 요약 메모 → TXT 열기 | 평균 시간 차이를 설명하는 메모와 상세 수치가 담긴 파일을 연다. |
| 요약 메모 → 메모 복사 | 짧은 비교 메모만 클립보드로 복사한다. |
| 분석 Excel 열기 | 전체 수치를 다섯 시트의 분석 파일로 연다. |
| 자료 폴더 → 보고서 폴더 | 요약 TXT·분석 Excel·실패 내역·SVG 그래프이 있는 폴더를 연다. |
| 자료 폴더 → 원본·로그 폴더 | 현재 선택한 시험의 JSON·CSV·전체 로그가 있는 폴더를 연다. |

메뉴 버튼은 클릭하거나 키보드로 포커스를 둔 뒤 Enter·Space·아래 화살표로 연다. 메뉴 항목은 방향키로 선택하고 Enter로 실행한다. Escape 또는 바깥 클릭으로 닫는다. 기록 선택 목록 옆의 새로고침은 기록 목록만 다시 읽으며 새 벤치를 실행하지 않는다.

## 비교 메모

메모는 조건별로 빠른 버전, 두 버전의 평균, 시간 차이와 완료 시간 감소율을 표시한다. 다음은 실제 결과가 아닌 문장 형식의 예시다.

> F01 준비 후 호출: vB 버전이 vA 버전보다 호출당 평균 20.00 ms 빨랐다. 평균은 vB 80.00 ms, vA 100.00 ms이며, vA 대비 완료 시간이 20.0% 짧았다(공동 유효 2/2블록).

같은 조건·블록에서 양쪽 모두 유효한 시행만 사용한다. 실패나 미수행을 0ms로 넣지 않는다. 한 블록만 비교했다면 반복 간 변동을 확인하지 못했다고 표시하고, 유효한 평균을 확보하지 못한 조건은 비교 불가로 설명한다. 평균이 같거나 표시 정밀도 내 차이라면 빠른 버전을 임의로 고르지 않는다.

메모는 빠른 버전을 먼저 쓰므로 감소율의 분모는 문장에 적힌 느린 버전의 평균이다. 예를 들어 기준이 100ms, 후보가 150ms이면 기준이 후보보다 33.3% 짧다고 쓴다. 반면 기준 대비 비교 표는 후보 시간이 기준보다 50% 증가했다고 표시한다. 분모와 비교 방향이 다른 표현이다.

서로 다른 실험의 시간을 합산해 전체 순위를 만들지 않는다. F01·F03·F04·S01은 호출당 시간, F02는 전체 작업 완료 시간으로 설명한다. 메모는 이번 측정의 관찰값이며 통계적 성능 우열을 확정하지 않는다.

## 앱에서 확인

1. **조건별 시간**에서 실험·조건·버전별 평균과 중앙값, 유효/계획 수를 본다.
2. **기준 버전 대비 비교**에서 시간 증가·감소와 공동 유효 블록 수를 확인한다.
3. 조건별 표의 행을 선택하면 해당 조건의 시행 목록이 표시된다.
4. 시행 목록은 실험·버전·상태로 좁힐 수 있다. 실패와 중단, 정리 실패, 미수행을 따로 고른다.
5. 시행을 선택하면 확인된 오류와 통계 제외 이유를 읽을 수 있다. 설명 옆의 **이 시행의 로그 열기**는 그 시행의 로그 폴더만 연다.

시행 필터와 **필터 초기화**는 시행 목록만 바꾸며, 위의 두 집계 표와 벤치 설정은 유지한다. 초기화는 적용 중인 필터가 있을 때 활성화한다. 이전 방식의 기록은 창 오른쪽 위 **앱 관리 → 이전 기록·앱 데이터 폴더 열기**에서 찾는다. 테마 변경도 앱 관리 메뉴에 있다.

기준 버전은 실행 기록에 저장된 첫 번째 릴리스다. 개별 버전 평균은 해당 버전의 유효 시행 전체로, 두 버전의 비교는 같은 블록에서 양쪽 모두 유효한 시행으로 계산한다. 따라서 두 표의 평균이 다를 수 있다.

`완료`는 실행이 끝났다는 뜻이다. 실패가 있으면 `완료 — 실패 N건 포함`으로 표시한다. 과거 `running` 기록은 실행 여부를 단정하지 않고 `실행 상태 확인 필요`로 표시한다.

## 그래프와 안정성

조건별 시간의 **그래프로 보기**에서 조건을 선택하고 평균 완료 시간·유효 완료율을 전환한다. 시간 막대는 해당 버전의 유효 시행 평균, 선은 최소–최대다. 신뢰구간이 아니며 조건마다 시간 축 범위가 다르다. 완료율 축은 0~100%다. 표본이 없으면 ‘측정 없음’으로 표시한다.

시행 상세의 **안정성 요약**은 접어서 둘 수 있다. 유효 완료 / 종료 시행, 개별 호출 판정, 시간 초과·응답 불일치·정리 실패, 범위·표준편차·성공 호출 P95, 부하 처리량을 표시한다. 사용자 중단과 미수행은 완료율 분모에서 제외한다. 구버전의 없는 판정은 추정하지 않는다. 호출이 성공했어도 시행의 최종 상태·정리는 실패할 수 있다. 계산식과 고부하 시험 범위는 [STABILITY.md](STABILITY.md)에 명시한다.

## 결과 폴더

벤치가 끝난 뒤 측정 밖에서 읽기용 파일을 만든다. 저장된 과거 결과는 **요약 메모 → TXT 열기**, **분석 Excel 열기** 또는 **자료 폴더 → 보고서 폴더**를 누르면 재실험 없이 생성한다.

```text
speed/reports/
└─ 2026-09-16_002552__3개버전__실행ID/
   ├─ 00_결과요약.txt
   ├─ 01_결과분석.xlsx
   ├─ 02_실패내역.txt
   └─ 03_결과그래프.svg
```

- **결과요약.txt**: 조건별 평균 시간 차이를 설명하는 메모를 먼저 읽고, 수행 현황·상세 수치·읽는 기준을 확인한다.
- **결과분석.xlsx**: 결과요약 / 블록비교 / 시행기록 / 호출표본 / 안정성의 다섯 시트. 숫자와 빈칸을 구분하고 필터·행/열 고정을 제공한다.
- **실패내역.txt**: 실패·제외 시행의 확인된 현상과 정리 상태. 직접 원인은 로그 근거 없이 단정하지 않는다.
- **결과그래프.svg**: 모든 조건의 시간 막대·최소–최대와 유효 완료 건수·비율. 브라우저에서 열거나 문서에 넣을 수 있다.

요약과 실패 내역은 UTF-8 BOM 텍스트다. Excel 파일은 저장 시점의 분석 사본이며, 셀을 편집해도 Desk 원본이나 집계 숫자가 자동 갱신되지는 않는다. 정렬·필터·추가 수식은 사본에서 사용할 수 있다. 파일 생성에 Excel 설치는 필요하지 않고, 열 때는 XLSX를 지원하는 프로그램이 필요하다.

F01·F03·F04·S01의 단위는 `ms/호출`, F02는 `ms/전체 작업`이다. 실패와 미수행을 0ms로 바꾸지 않는다. 개별 호출에 반복된 시행 대표시간을 평균 내지 않도록 시행과 호출을 다른 시트로 나눈다.

기존 JSON·CSV·로그는 `speed/local-runs/<실행 ID>`에 그대로 남는다. **자료 폴더 → 원본·로그 폴더**로 열 수 있다. 결과 폴더 안의 숨김 파일 `.report.json`에는 형식 버전, 생성 시각, 원본 기록을 직렬화한 스냅샷의 해시와 보고서 파일 해시가 들어 있다.

동일한 기록·파일은 재사용한다. 기록이 바뀌었거나 사용자가 보고서를 편집했다면 `사본-N` 폴더에 새 파일을 만들어 이전 파일을 보존한다. 보고서 저장에 실패하면 재시도 안내를 표시하며, 이 문제를 벤치 실패로 기록하지 않는다. Excel 한 시트의 최대 행 수를 넘는 경우에는 원본 자료를 사용하도록 안내한다.

## 구현 기준

문장형 메모의 보고서 형식은 4이다. 이전 형식의 결과는 덮어쓰지 않고 새 사본으로 생성한다.

앱·TXT·Excel은 공통 `SpeedReport` 집계 모델을 사용한다. 유효성은 `SpeedAnalysis.IsValid`로 공유한다. 파일은 임시 폴더에서 모두 작성한 뒤 보고서 폴더로 옮기므로 작성 중 파일을 완성본으로 보여주지 않는다.

XLSX 출력은 .NET의 ZIP·XML 기능을 사용하며, 표준 SpreadsheetML의 통합 문서·시트·스타일 관계를 따른다. 외부 패키지나 Office 자동화에 의존하지 않는다. [Microsoft: SpreadsheetML 문서 구조](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document)
