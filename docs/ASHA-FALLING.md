# 아샤 — 빈 클릭 영역 제외와 자유 낙하

2026-09-20: 현재 Desk는 [연속 구간과 접촉 계산](ASHA-CONTACT-GEOMETRY.md)을 사용한다. 버튼·글줄·그래프의 실제 윗면과 화면 변경을 반영하며 발판 없는 화면의 반복 낙하도 방지한다. 아래 내용은 선행 구현 기록이다.

> **후속 수정 · 2026-09-20:** 기존 고양이의 이름은 아라이고 여우 아샤가 추가되었다. 두 캐릭터의 자유 낙하는 이제 발이 지나가는 높이와 착지할 몸 공간을 검사한다. 글자·입력칸과 겹쳐 놓거나 옆면에 닿아도 즉시 복귀하지 않고 계속 떨어진다. 낙하 중의 일시적 UI 겹침은 허용하고 착지에서는 가림을 금지한다. 아래의 몸 전체 충돌로 낙하를 취소하는 설명과 61개 검사는 선행 구현 기록이며 [현재 설계·66개 검사](CHARACTERS.md)가 우선한다.

2026-09-20 · Desk v0.4.0 후속 수정이다.

## 문제와 수정

체크박스의 클릭 영역은 글자 오른쪽까지 늘어나지만, 화면에는 그 부분이 그려지지 않는다. 기존 로직은 `ButtonBase`의 전체 배치 사각형을 발판으로 사용하여 이 빈 영역에도 아샤를 세웠다. 접기 메뉴의 헤더와 투명한 글자 버튼도 같은 영향을 받았다.

이제 버튼 템플릿에 실제로 그려진 배경·테두리가 버튼 전체를 감싸는지 확인한다. 전체 프레임이 있으면 그 윗면을, 없으면 실제 표시 기호와 텍스트 줄을 사용한다. 투명한 클릭 영역은 제외한다. 체크 표시처럼 두 발을 지지하기에 짧은 도형은 장애물로만 인식한다. 컨트롤의 원래 클릭 영역과 포커스는 바꾸지 않는다.

템플릿 내부에서 반복되는 `Row` 같은 이름은 소유 버튼의 이름으로 구분한다. 서로 다른 체크박스의 텍스트 발판이 같은 ID로 저장되는 경우도 방지한다. 이는 실행 중 발판 식별을 개선한 것이며, 모든 UI 구조 변경에 대한 영구 ID 체계를 도입한 것은 아니다.

## 놓았을 때의 동작

1. 마우스를 놓거나 드래그 중 캡처가 해제되면 현재 화면의 발판을 다시 읽는다.
2. 실제 발판에 이미 서 있으면 짧은 착지와 몸 정돈을 수행한다.
3. 빈 공간에 있으면 그 자리에서 아래로 떨어진다. 가로 위치를 유지하며 속도가 점차 증가한다.
4. 두 발을 받치고 몸이 들어갈 공간이 있는 첫 발판에 닿으면 낙하를 끝낸다. 낙하 거리만큼 착지 자세의 강도를 조절하고 몸을 정돈한다.
5. 낙하 중 화면이 바뀌면 새 지도로 계속 검사한다. 사라진 발판에는 착지하지 않는다. 입력·스크롤은 다음 자율 탐색을 늦추지만 진행 중인 낙하를 공중에서 멈추지 않는다.

아샤의 자율 점프 경로와 자유 낙하는 별도 상태이다. 자유 낙하는 시작점에 발판이 없어도 시작할 수 있다. 기존 40ms 이동 타이머에서 중력 1,400 DIP/s², 최대 속도 720 DIP/s로 계산하며, 한 번의 계산 시간은 최대 80ms로 제한한다. 속도 상한에 도달하는 구간도 나누어 적분한다.

한 프레임의 끝점만 검사하지 않고 몸 전체가 지나가는 영역을 검사한다. 빠르게 떨어져도 얇은 글자나 버튼을 통과하지 않는다. 착지는 지도에 샘플링된 점으로 가로 이동시키지 않고 현재 x에서 정확한 발판 높이에 맞춘다.

## 예외와 정지

아래에 발판이 없고 화면 끝에 도달했거나, 몸이 먼저 닿는 장애물 때문에 안전한 수직 낙하가 불가능하면 검증된 다른 발판으로 복귀해 짧게 나타난다. 화면 끝이나 장애물 옆면을 보이지 않는 바닥으로 취급하지 않는다. 안전한 발판이 하나도 없으면 잠시 숨는다. 내용 위에 겹쳐 놓은 경우도 이 복구 규칙을 사용한다.

움직임 끄기·앱 비활성화·설정 팝업·숨기기·벤치 중 정지에서는 낙하 타이머도 멈추고 안전한 자리로 즉시 정리한다. 산책만 끈 상태에서는 사용자가 놓은 아샤의 낙하는 수행한다. 새 타이머·Unity 실행·AI 호출을 추가하지 않으며 벤치의 명령·시간 측정·판정·집계를 변경하지 않는다.

## 디자인 근거와 검증

Desktop 자동 검사 61개가 모두 통과했다. 기록은 `TestResults/Desktop.AshaFalling.trx`이다. 별도 WPF 낙하 검사와 실제 준비 화면 캡처도 확인했다.

[디자인 작업 기준](../design/UI-DESIGN-WORKFLOW.md), [아샤](ASHA.md), [텍스트 줄 발판](ASHA-FINE-SURFACES.md), [모션](MOTION.md)을 확인했다. 2026-09-20에 frontend-design과 UI/UX Pro Max의 외부 SKILL.md 원문을 다시 열어, 제품 고유 행동·입력 우선·공간적 연속성·움직임 끄기 원칙을 적용했다. 기존 UI의 색·배치·글꼴은 유지하고, 웹 기술 예시나 새로운 장식 효과는 도입하지 않았다. 외부 스킬을 설치하거나 검색 스크립트를 실행한 것은 아니다.

- 중력 가속, 첫 발판 착지, 고속 낙하 중 관통 방지, 발판 제거, 막힌 경로, 화면 경계와 속도 상한의 계산을 검사한다.
- 실제 WPF 컨트롤에서 체크박스·라디오 버튼·투명 버튼·접기 메뉴의 빈 영역 제외와 기존 클릭 영역을 확인한다. 줄바꿈·비활성 컨트롤도 검사한다.
- 드래그 해제와 캡처 해제, 낙하 도중 스크롤과 발판 삭제, 움직임 끄기, 발판 없는 화면의 숨김을 검사한다.
- 별도 상태 폴더를 사용하는 실제 준비 화면에서 낙하와 착지를 렌더링한다. 새 실험은 실행하지 않는다. 1440×850, 960×660과 확대 배율·스크롤에서도 발판을 확인한다.
